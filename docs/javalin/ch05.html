第 5 章

数据库

到目前为止，应用重启一次数据就全没了。这一章接上数据库：先搞懂关系模型， 再用 Hibernate ORM 把 Java 对象和数据库表对应起来， 最后用 Flyway 管理表结构的演进。这是整本教程技术密度最高的一章，慢慢读。

本章目标

  • 看懂实体-关系图，理解主键、外键、一对多
  • 知道 Java 有哪些数据访问方案，以及为什么本教程选 Hibernate
  • 会用 @Entity 把类映射成表，会写一对多关联
  • 理解 EntityManager 和“实体的四种状态”——这是 Hibernate 最大的认知门槛
  • 会用 JPQL 查询，知道 LAZY 和 EAGER 的区别
  • 给每个请求配好事务边界
  • 会用 Flyway 做数据库迁移

SQL 数据库

关系型数据库把数据存在表里。表有固定的几列（定义了实体的属性）和任意多行（每行是一条实际数据）。 其中有两种特殊的列：

  • 主键（primary key）：唯一标识一行。通常是一个自增整数 id。
  • 外键（foreign key）：存着另一张表（或同一张表）某一行的主键值，由此在两行之间建立关系。

NoSQL 和反范式化

不遵循关系模型的数据库统称 NoSQL。它们常用“集合 + 文档”代替“表 + 行”， 并且通常不支持 JOIN。所以在 NoSQL 里存上面的数据，更自然的设计是把角色名直接写进每个用户文档： 

# 关系型（范式化）              # 文档型（反范式化）
roles:  {id:1, name:"管理员"}   users: {id:7, username:"john", role:"管理员"}
users:  {id:7, role_id:1}       users: {id:8, username:"susan", role:"普通用户"}

反范式化用数据重复换查询速度：列用户和角色不需要 JOIN。 代价是改一个角色名要更新成千上万个文档。

原书的结论今天依然成立：中小型应用用哪种都行，性能几乎没差别。 关系型数据库在保证一致性（ACID：原子性、一致性、隔离性、持久性）上做得极致， 而社交博客这种有大量关联的数据正是它的主场。本教程全程用关系型。

Java 的数据访问方案

原书比较了几种 Python 方案，最后选了 Flask-SQLAlchemy。 Java 这边的选项更多，按“抽象层次”从低到高排：

方案你写什么优点缺点
JDBC（标准库）SQL 字符串 + 手动取结果集每一列没有任何魔法，完全可控样板代码极多，20 行代码干 1 行的事
JDBI 3SQL + 自动映射到 record轻量，SQL 可见，学习成本低关联关系要自己处理
jOOQ用 Java 方法链拼 SQL（类型安全）编译期检查 SQL，对复杂查询极强需要代码生成；商业数据库要付费
MyBatisXML / 注解里写 SQL国内生态成熟配置较多
Hibernate ORM（JPA）给类加注解，很多时候完全不写 SQL关联关系、脏检查、缓存、迁移生态最全抽象厚，出问题时要懂它背后干了什么
☀ 为什么本教程选 Hibernate

一个理由：它和 SQLAlchemy 是同一类东西。原书第 5、11、12 章大量篇幅在讲 db.relationship、backref、lazy='dynamic'、 多对多关联表、自引用关系 —— 这些概念在 Hibernate 里有一一对应的东西 （@OneToMany、mappedBy、FetchType.LAZY、@JoinTable）。 换成 JDBI 的话第 12 章就得整章重写。

代价是你得理解它的工作模型。本章会花力气把这件事讲透，因为 “不理解 Hibernate 在干什么”是 Java Web 新手最常见的坑。

Jakarta Persistence 和 Hibernate 的关系

这里有个容易混的地方：Jakarta Persistence（旧名 JPA）是一套规范， 定义了 @Entity、EntityManager 这些接口； Hibernate ORM 是这套规范的实现（也是最主流的那个）。

实践意义：你写的注解和 EntityManager 调用是标准的，理论上能换成别的实现 （EclipseLink、OpenJPA）。但 Hibernate 也有自己的增强 API，用了就绑定了。 本教程尽量只用标准 API。

ⓘ H2 相当于原书的 SQLite

原书开发时用 SQLite（一个文件就是一个数据库，不需要装服务器）。 Java 世界的等价物是 H2：纯 Java 实现，可以存文件也可以纯内存， 而且能模拟 PostgreSQL 的方言，这让“开发用 H2、生产用 Postgres”的差异比 “开发 SQLite、生产 Postgres”小得多。

jdbc:h2:mem:test;MODE=PostgreSQL;DB_CLOSE_DELAY=-1  # 纯内存，测试用
jdbc:postgresql://localhost:5432/javalinky     # 生产

连接地址故意没写在这里 —— 它每个环境都不一样，应该来自环境变量。 我们在代码里覆盖： 

package com.example.javalinky.db;

import io.javalin.http.Context;
import jakarta.persistence.EntityManager;
import jakarta.persistence.EntityManagerFactory;
import jakarta.persistence.Persistence;
import org.flywaydb.core.Flyway;

import java.util.HashMap;
import java.util.Map;

public final class Db {

    public static final String CTX_KEY = "entityManager";

    private static EntityManagerFactory emf;

    /** 应用启动时调一次：先跑迁移，再建 EntityManagerFactory */
    public static void init(String jdbcUrl, String user, String password) {
        // 1. Flyway 先把表结构升到最新
        Flyway.configure()
              .dataSource(jdbcUrl, user, password)
              .locations("classpath:db/migration")
              .load()
              .migrate();

        // 2. 再创建 EMF（此时 hbm2ddl=validate 的校验才会通过）
        Map<String, Object> overrides = new HashMap<>();
        overrides.put("jakarta.persistence.jdbc.url", jdbcUrl);
        overrides.put("jakarta.persistence.jdbc.user", user);
        overrides.put("jakarta.persistence.jdbc.password", password);
        emf = Persistence.createEntityManagerFactory("javalinky", overrides);
    }

    public static EntityManagerFactory emf() {
        if (emf == null) throw new IllegalStateException("Db.init() 还没调用");
        return emf;
    }

    /** 取当前请求的 EntityManager（由过滤器放进 Context） */
    public static EntityManager em(Context ctx) {
        EntityManager em = ctx.attribute(CTX_KEY);
        if (em == null) throw new IllegalStateException("当前请求没有 EntityManager");
        return em;
    }

    public static void close() {
        if (emf != null) emf.close();
    }

    private Db() {}
}

定义实体

“模型”指应用里需要持久化的实体。在 ORM 里，一个模型就是一个类，它的字段对应表的列。 

package com.example.javalinky.model;

import jakarta.persistence.*;
import java.util.ArrayList;
import java.util.List;

@Entity
@Table(name = "roles")
public class Role {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(length = 64, unique = true, nullable = false)
    private String name;

    @Column(name = "is_default", nullable = false)
    private boolean defaultRole;

    @Column(nullable = false)
    private int permissions;

    /** 关系的"一"这一侧。mappedBy 指向 User 里那个字段的名字 */
    @OneToMany(mappedBy = "role", fetch = FetchType.LAZY)
    private List<User> users = new ArrayList<>();

    // JPA 要求有一个无参构造器（可以是 protected）
    protected Role() {}

    public Role(String name) {
        this.name = name;
    }

    public Long getId() { return id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public boolean isDefaultRole() { return defaultRole; }
    public void setDefaultRole(boolean v) { this.defaultRole = v; }
    public int getPermissions() { return permissions; }
    public void setPermissions(int p) { this.permissions = p; }
    public List<User> getUsers() { return users; }

    @Override
    public String toString() {
        return "Role[" + name + "]";
    }
}

package com.example.javalinky.model;

import jakarta.persistence.*;
import java.time.Instant;

@Entity
@Table(name = "users", indexes = {
    @Index(name = "ix_users_email", columnList = "email", unique = true),
    @Index(name = "ix_users_username", columnList = "username", unique = true)
})
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(length = 64, nullable = false)
    private String email;

    @Column(length = 64, nullable = false)
    private String username;

    @Column(name = "password_hash", length = 128)
    private String passwordHash;

    @Column(nullable = false)
    private boolean confirmed = false;

    @Column(name = "member_since", nullable = false)
    private Instant memberSince = Instant.now();

    /** 关系的"多"这一侧：真正的外键列在这里 */
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "role_id")
    private Role role;

    protected User() {}

    public User(String email, String username) {
        this.email = email;
        this.username = username;
    }

    public Long getId() { return id; }
    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }
    public String getUsername() { return username; }
    public void setUsername(String username) { this.username = username; }
    public String getPasswordHash() { return passwordHash; }
    public void setPasswordHash(String h) { this.passwordHash = h; }
    public boolean isConfirmed() { return confirmed; }
    public void setConfirmed(boolean c) { this.confirmed = c; }
    public Instant getMemberSince() { return memberSince; }
    public Role getRole() { return role; }
    public void setRole(Role role) { this.role = role; }

    @Override
    public String toString() {
        return "User[" + username + "]";
    }
}
⚠ 实体类不能用 record

上一章我们到处用 record，这里却用了老式的类加 getter/setter。原因是 Hibernate 需要可变对象：它靠“修改字段”来表达更新，靠无参构造器来创建代理对象。 record 是不可变的，做不到。

所以本教程的分工是：实体类用普通类，传给模板和 API 的数据用 record。 这个分界其实是好事 —— 第 14 章会讲为什么不该把实体直接序列化成 JSON。

常用的字段映射注解

注解作用SQLAlchemy 的对应
@Entity声明这个类是实体继承 db.Model
@Table(name=)指定表名（默认用类名）__tablename__
@Id主键primary_key=True
@GeneratedValue(IDENTITY)主键由数据库自增生成同上（默认行为）
@Column(name=)列名。默认把 camelCase 转成 snake_case列名即属性名
@Column(nullable=false)非空nullable=False
@Column(unique=true)唯一约束unique=True
@Column(length=)varchar 长度db.String(64)
@Index（在 @Table 里）索引index=True
@Lob / @Column(columnDefinition="text")长文本db.Text()
@Enumerated(EnumType.STRING)枚举存成字符串db.Enum
@Transient这个字段不入库—
@ManyToOne + @JoinColumn多对一，外键在本表db.ForeignKey
@OneToMany(mappedBy=)一对多，外键在对方表db.relationship(backref=)
@ManyToMany + @JoinTable多对多（第 12 章）secondary=
ⓘ 关系的两侧，只有一侧是“真的”

数据库里只有一个 users.role_id 列。 @ManyToOne 那一侧（User.role）对应这个列，是拥有方； @OneToMany(mappedBy="role") 那一侧（Role.users）只是反向视图， 不产生任何列。

这意味着：要建立关系，必须设置拥有方。 只往 role.getUsers().add(user) 里加而不设 user.setRole(role)， 数据库里什么都不会变。这是 JPA 新手最常见的 bug。

Flyway：数据库迁移

原书用 db.create_all() 建表，然后指出它的致命问题： 模型变了它不会更新已有的表，只能删表重建（数据全丢）。 于是引入 Flask-Migrate（Alembic）。

Java 这边的对应工具是 Flyway（或 Liquibase）。 Flyway 的模型比 Alembic 更简单，也更容易讲清楚：

☀ Flyway 和 Alembic 的一个重要区别

Alembic 可以自动生成迁移脚本（对比模型和数据库的差异）， 原书也提醒过“自动生成的脚本必须人工审查，否则改列名可能被识别成删列 + 加列，数据就丢了”。

Flyway 社区版不自动生成，SQL 要你自己写。 一开始觉得麻烦，但实际上这是优点：你完全清楚将在生产库上执行什么， 不存在“自动生成的脚本悄悄删了一列”这种事故。

第一个迁移

迁移文件放在 src/main/resources/db/migration/， 命名规则是 V<版本>__<描述>.sql（两个下划线）： 

CREATE TABLE roles (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name        VARCHAR(64) NOT NULL UNIQUE,
    is_default  BOOLEAN     NOT NULL DEFAULT FALSE,
    permissions INTEGER     NOT NULL DEFAULT 0
);

CREATE INDEX ix_roles_is_default ON roles (is_default);

CREATE TABLE users (
    id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    email         VARCHAR(64)  NOT NULL,
    username      VARCHAR(64)  NOT NULL,
    password_hash VARCHAR(128),
    confirmed     BOOLEAN      NOT NULL DEFAULT FALSE,
    member_since  TIMESTAMP(6) WITH TIME ZONE NOT NULL,
    role_id       BIGINT       REFERENCES roles (id)
);

CREATE UNIQUE INDEX ix_users_email    ON users (email);
CREATE UNIQUE INDEX ix_users_username ON users (username);
ⓘ GENERATED BY DEFAULT AS IDENTITY 是什么

这是 SQL 标准的自增列写法，PostgreSQL 10+ 和 H2 都支持。 （老教程里常见的 SERIAL 是 PostgreSQL 的专有语法， AUTO_INCREMENT 是 MySQL 的。用标准写法可以让同一份脚本同时跑在 H2 和 Postgres 上。）

TIMESTAMP WITH TIME ZONE 对应 Java 的 Instant， 数据库内部按 UTC 存储 —— 这正是第 3 章讲的时间策略。

EntityManager 与实体的四种状态

这一节是本章的核心。原书对应的内容是 db.session： “改动通过数据库会话管理，add() 加进会话，commit() 真正写库”。 Hibernate 的模型类似但更精细，而且不理解它就会写出各种诡异的 bug。

EntityManager（Hibernate 里也叫 Session）是一个短命的工作单元。 它内部维护一个“一级缓存”，记录着它当前管理的所有实体对象。 一个实体对象相对于某个 EntityManager，有四种状态：

☀ 和 SQLAlchemy 的异同
操作SQLAlchemyJPA / Hibernate
把新对象纳入管理db.session.add(obj)em.persist(obj)
更新已有对象改字段即可（也可 add）改字段即可（托管状态下）
把游离对象改动合并回来db.session.merge(obj)em.merge(obj)
删除db.session.delete(obj)em.remove(obj)
按主键查Model.query.get(id)em.find(Model.class, id)
提交db.session.commit()em.getTransaction().commit()
回滚db.session.rollback()em.getTransaction().rollback()

几乎一一对应。最大的差别是 Flask-SQLAlchemy 把 db.session 藏在了“请求上下文”里（看起来像全局变量），而 JPA 要你明确地创建、传递和关闭 EntityManager。

给每个请求配事务边界

那么 EntityManager 该活多久？答案是：一个请求一个。 这和 Flask-SQLAlchemy 的行为完全一致。 

package com.example.javalinky.db;

import io.javalin.config.JavalinConfig;
import jakarta.persistence.EntityManager;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public final class UnitOfWork {

    private static final Logger log = LoggerFactory.getLogger(UnitOfWork.class);

    public static void install(JavalinConfig config) {

        // 请求开始：开一个 EntityManager 和事务
        config.routes.before(ctx -> {
            EntityManager em = Db.emf().createEntityManager();
            ctx.attribute(Db.CTX_KEY, em);
            em.getTransaction().begin();
        });

        // 请求结束：按状态码决定提交还是回滚，然后一定要关掉
        config.routes.after(ctx -> {
            EntityManager em = ctx.attribute(Db.CTX_KEY);
            if (em == null) return;
            try {
                var tx = em.getTransaction();
                if (!tx.isActive()) return;
                if (ctx.statusCode() >= 400) {
                    tx.rollback();
                } else {
                    tx.commit();
                }
            } catch (RuntimeException e) {
                log.error("提交事务失败", e);
                safeRollback(em);
                throw e;
            } finally {
                em.close();          // 必须关，否则连接池会耗尽
            }
        });
    }

    private static void safeRollback(EntityManager em) {
        try {
            if (em.getTransaction().isActive()) em.getTransaction().rollback();
        } catch (RuntimeException ignored) {
            // 回滚本身失败就只能放弃了
        }
    }

    private UnitOfWork() {}
}
🔎 深入：这个模式的名字和争议

“整个请求共享一个数据库会话、在视图渲染期间还保持打开”这个模式叫 Open Session in View。它的好处是模板里可以放心地点 user.getRole().getName()（懒加载还能工作）； 坏处是数据库连接被占用的时间包含了渲染时间，高并发时连接池压力大， 而且容易在模板里无意触发大量查询（N+1 问题，第 12、16 章会详谈）。

更严格的做法是：在处理器里就把数据全部取出来转成 record（DTO）， 关掉 EntityManager 再渲染。本教程为了贴近原书的写法用前者， 但到第 16 章我们会看到它的代价，并给出改进方向。 知道自己在用哪种模式、代价是什么，比盲目追求"最佳实践"重要。

增删改查

按原书的顺序，用“仓储类”（Repository）把数据访问集中起来：

package com.example.javalinky.db;

import com.example.javalinky.model.Role;
import com.example.javalinky.model.User;
import jakarta.persistence.EntityManager;
import jakarta.persistence.NoResultException;
import java.util.List;
import java.util.Optional;

public class UserRepository {

    private final EntityManager em;

    public UserRepository(EntityManager em) {
        this.em = em;
    }

    // ---------- 增 ----------
    public User save(User user) {
        em.persist(user);        // 瞬态 → 托管
        return user;
    }

    // ---------- 查 ----------
    /** 按主键查，相当于 Model.query.get(id) */
    public Optional<User> findById(long id) {
        return Optional.ofNullable(em.find(User.class, id));
    }

    /** 按条件查一个，相当于 filter_by(...).first() */
    public Optional<User> findByEmail(String email) {
        return em.createQuery(
                "select u from User u where lower(u.email) = lower(:email)", User.class)
            .setParameter("email", email)
            .getResultStream()      // 比 getSingleResult() 好：查不到不会抛异常
            .findFirst();
    }

    public Optional<User> findByUsername(String username) {
        return em.createQuery(
                "select u from User u where u.username = :name", User.class)
            .setParameter("name", username)
            .getResultStream()
            .findFirst();
    }

    /** 查全部，相当于 Model.query.all() */
    public List<User> findAll() {
        return em.createQuery("select u from User u order by u.username", User.class)
                 .getResultList();
    }

    /** 计数，相当于 Model.query.count() */
    public long count() {
        return em.createQuery("select count(u) from User u", Long.class)
                 .getSingleResult();
    }

    public boolean emailExists(String email) {
        return em.createQuery(
                "select count(u) from User u where lower(u.email) = lower(:email)", Long.class)
            .setParameter("email", email)
            .getSingleResult() > 0;
    }

    // ---------- 改 ----------
    // 不需要写！托管对象改字段，提交事务时自动 UPDATE。

    // ---------- 删 ----------
    public void delete(User user) {
        em.remove(user);
    }
}

JPQL：面向对象的查询语言

注意上面查询里写的不是 SQL，是 JPQL。 它看起来像 SQL，但操作的是实体和字段名，不是表和列名：

SQL（表名、列名）
select u.* from users u
  join roles r on u.role_id = r.id
 where r.name = '管理员'
 order by u.member_since desc
JPQL（类名、字段名）
select u from User u
  join u.role r
 where r.name = :roleName
 order by u.memberSince desc

JPQL 的好处是数据库无关（Hibernate 负责翻译成对应方言的 SQL）， 而且 join u.role 不用写 ON 条件 —— 映射关系里已经说明了。

⚠ 永远用参数绑定，不要拼字符串
✗ SQL 注入漏洞
em.createQuery(
  "select u from User u where u.email = '"
  + email + "'", User.class)
✓ 参数绑定
em.createQuery(
  "select u from User u where u.email = :e",
  User.class).setParameter("e", email)

如果 email 的值是 ' or '1'='1，第一种写法会把整张表的用户全查出来。 参数绑定则把值交给驱动单独传输，数据永远不会被当成代码执行。

懒加载：最常见的两个坑

原书讲了 SQLAlchemy 的 lazy 选项（select / joined / subquery / dynamic）。 JPA 只有两种，但背后的取舍一样：

FetchType行为SQLAlchemy 的对应
LAZY（推荐默认）关联对象先不查，第一次访问它时再发一条 SQLlazy='select'
EAGER查主对象时就 JOIN 把关联一起取出来lazy='joined'
⚠ 坑一：LazyInitializationException

懒加载需要 EntityManager 还开着。如果你把实体返回到 EM 关闭之后再访问懒字段： 

org.hibernate.LazyInitializationException:
  could not initialize proxy [com.example.javalinky.model.Role#1] - no Session

上一节的 UnitOfWork 让 EM 活到请求结束（包括模板渲染），所以本教程里不会碰到。 但如果你把实体扔进后台线程或缓存，就会撞上它。 解决办法：在 EM 还开着的时候就把需要的数据取出来，转成 record。

⚠ 坑二：N+1 查询

列 100 个用户，模板里显示每个人的角色名：

select * from users                      ← 1 条
select * from roles where id = 1         ← 第 1 个用户的角色
select * from roles where id = 2         ← 第 2 个用户的角色
...                                      ← 一共 100 条

这就是 N+1：1 条主查询 + N 条关联查询。解决办法是用 join fetch 一次取完：

em.createQuery(
    "select u from User u join fetch u.role order by u.username", User.class)
  .getResultList();     // 只发 1 条带 JOIN 的 SQL

第 16 章会讲怎么发现自己写出了 N+1（而不是靠肉眼检查）。

☀ 一条简单的纪律

所有 @ManyToOne 和 @OneToMany 都写成 LAZY， 需要关联数据时在查询里显式 join fetch。

为什么不用 EAGER？因为 EAGER 是“无条件生效”的： 哪怕某个页面只需要用户名，也会被迫 JOIN 一堆表。 LAZY + 按需 fetch 把决定权交回给每个查询。

package com.example.javalinky;

import com.example.javalinky.db.Db;

import io.javalin.Javalin;

        // 1. 数据库：Flyway 迁移 + EntityManagerFactory
        Db.init(
            System.getenv().getOrDefault("DATABASE_URL",
                "jdbc:h2:./data/javalinky-dev;MODE=PostgreSQL"),
            System.getenv().getOrDefault("DATABASE_USER", "sa"),
            System.getenv().getOrDefault("DATABASE_PASSWORD", ""));

                h.setSessionHandler(Sessions.handler(false)));

            UnitOfWork.install(config);
