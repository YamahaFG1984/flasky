Javalin 是什么

原书第 1 章开头说：Flask 小到你熟悉之后可以读懂它的全部源码。 Javalin 也是这种尺寸的框架 —— 核心一个 jar，依赖只有两个：

依赖作用相当于 Flask 的
Jetty 12内嵌的 HTTP 服务器 + Servlet 容器，负责监听端口、解析 HTTP、管理线程Werkzeug（WSGI）
SLF4J日志门面（只是接口，具体实现要你自己选，比如 Logback）Python 的 logging

注意这里和 Flask 的一个重要区别： Flask 的开发服务器只能用于开发，上线要换 Gunicorn / uWSGI； 而 Javalin 内嵌的 Jetty 就是生产级服务器，开发和上线跑的是同一个东西。 第 17 章我们会看到，部署一个 Javalin 应用只需要 java -jar。

和 Flask 一样，Javalin 核心里没有数据库、没有表单校验、没有用户认证。 这些都由你自己挑库来补。Javalin 官方提供了一小组“卫星模块”，其余用任何 Java 库都行：

第一步：装 JDK 21

Java 程序需要 JDK（Java Development Kit，含编译器 javac 和运行时 java）。 Javalin 7 要求 Java 17 或更高。本教程统一用 Java 21，原因有两个： 它是长期支持（LTS）版本，而且它带来的几个新语法（record、var、文本块、虚拟线程） 能让 Java 代码写起来比你印象中的 Java 短得多。

怎么知道自己装没装

java -version

如果输出里的大版本号 ≥ 21，你可以直接跳到下一节。否则：

推荐方式：用版本管理器

Java 世界的版本管理器相当于 Python 的 pyenv：它让你在一台机器上并存多个 JDK，按项目切换。 最常用的是 SDKMAN!（Linux / macOS / WSL）： 

# 安装 SDKMAN!（只需一次）
curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"

# 看看有哪些 JDK 可装（列表很长，按 q 退出）
sdk list java

# 装一个 Java 21（Temurin 是 Eclipse 基金会维护的免费发行版）
sdk install java 21.0.5-tem

# 查看当前用的是哪个
sdk current java

Windows 用户如果不想装 WSL，用 winget 最省事：

winget install EclipseAdoptium.Temurin.21.JDK
ⓘ “JDK 发行版”是什么意思

Java 的语言规范是公开的，任何人都可以按规范编译出一套 JDK。 所以你会看到 Temurin、Oracle JDK、Amazon Corretto、Azul Zulu、GraalVM 等等很多名字。 对本教程来说它们完全等价，挑一个带长期免费更新的就行（Temurin 和 Corretto 都是安全选择）。

为什么 Java 不需要虚拟环境

原书第 1 章花了整整四节讲虚拟环境（python3 -m venv venv、source venv/bin/activate、pip install）。 这部分在 Java 里直接消失了，值得解释一下为什么。

Python 的问题在于：pip install flask 默认把包装到解释器自己的目录里， 全局共享。两个项目要不同版本的同一个库就会打架，所以才需要给每个项目复制一份解释器（虚拟环境）。

Java 走的是另一条路。依赖不装进 JDK，而是：

  1. 以 jar 文件的形式下载到一个全局缓存（~/.m2/repository），同一个库的不同版本各占一个目录，互不干扰；
  2. 每个项目在 pom.xml 里声明自己要哪些坐标和版本；
  3. 运行时 Maven 按这份声明拼出这个项目专属的 classpath（“这次运行能看到哪些 jar”）。
💡 心里的对应关系
  • venv/ + pip install  →  ~/.m2/repository（下载缓存，所有项目共用）
  • requirements.txt  →  pom.xml 的 <dependencies>（声明，进版本控制）
  • pip freeze  →  mvn dependency:tree（看实际解析出来的完整依赖）
  • source venv/bin/activate  →  不存在，不需要

第二步：Maven

Java 有两个主流构建工具：Maven（配置是 XML，声明式，约定多）和 Gradle（配置是 Kotlin/Groovy 代码，灵活，增量构建快）。 本教程用 Maven，因为它的配置文件“所有东西都写明了”，对初学者更容易读懂 —— 没有隐藏逻辑。

装 Maven

# SDKMAN!
sdk install maven

# macOS Homebrew
brew install maven

# Windows
winget install Apache.Maven

# 验证
mvn -version

Maven 的两个核心概念

坐标（coordinates）。每个 Java 库由三段唯一确定，俗称 GAV： 

<dependency>
  <groupId>io.javalin</groupId>      <!-- 组织，一般是反写域名 -->
  <artifactId>javalin</artifactId>   <!-- 这个库自己的名字 -->
  <version>7.2.3</version>           <!-- 版本 -->
</dependency>

生命周期（lifecycle）。Maven 把构建拆成固定的几个阶段，你执行某个阶段， 它会自动把前面的阶段都跑一遍。日常只要记住四个命令：

第三步：创建 Javalinky 项目

Maven 对目录结构有强约定：源码必须放在 src/main/java，资源放 src/main/resources， 测试放 src/test/java。约定的好处是所有 Java 项目长得一样，换个项目你立刻知道去哪找东西。

我们手动把骨架建出来，这样每个目录是干什么的你都清楚：

mkdir -p javalinky/src/main/java/com/example/javalinky
mkdir -p javalinky/src/main/resources
mkdir -p javalinky/src/main/jte
mkdir -p javalinky/src/test/java/com/example/javalinky
cd javalinky

pom.xml

pom.xml（Project Object Model）是整个项目的清单。 下面是本章要用的最小版本 —— 后面每一章都会往里加几行，所以请花两分钟看懂每一段： 

<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
                             http://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>

  <!-- 1. 本项目自己的坐标 -->
  <groupId>com.example</groupId>
  <artifactId>javalinky</artifactId>
  <version>1.0-SNAPSHOT</version>
  <packaging>jar</packaging>

  <!-- 2. 把版本号集中在一处，后面引用 ${javalin.version} 即可 -->
  <properties>
    <maven.compiler.release>21</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    <javalin.version>7.2.3</javalin.version>
    <logback.version>1.5.20</logback.version>
  </properties>

  <!-- 3. 依赖 -->
  <dependencies>
    <dependency>
      <groupId>io.javalin</groupId>
      <artifactId>javalin</artifactId>
      <version>${javalin.version}</version>
    </dependency>

    <!-- Javalin 只依赖 SLF4J 接口，不带实现。不加这一条启动时会警告“没有日志实现” -->
    <dependency>
      <groupId>ch.qos.logback</groupId>
      <artifactId>logback-classic</artifactId>
      <version>${logback.version}</version>
    </dependency>
  </dependencies>

  <!-- 4. 插件：告诉 Maven 用什么工具干活 -->
  <build>
    <plugins>
      <!-- 用 mvn exec:java 直接运行 main 方法，省得手拼 classpath -->
      <plugin>
        <groupId>org.codehaus.mojo</groupId>
        <artifactId>exec-maven-plugin</artifactId>
        <version>3.5.0</version>
        <configuration>
          <mainClass>com.example.javalinky.App</mainClass>
        </configuration>
      </plugin>
    </plugins>
  </build>
</project>
ⓘ 1.0-SNAPSHOT 是什么意思

Maven 里带 -SNAPSHOT 后缀的版本表示“还在开发中、随时会变”。 自己的项目在没发布之前一直挂着 SNAPSHOT 就好，不用管它。

第一次编译：让 Maven 把依赖拉下来

先建一个最简单的类，好让编译器有事可做：

package com.example.javalinky;

import io.javalin.Javalin;

public class App {
    public static void main(String[] args) {
        // 下一章我们才真正启动服务器，这里只验证 Javalin 能被 import
        System.out.println("Javalin 已就位：" + Javalin.class.getName());
    }
}

mvn compile

第一次执行会刷很多 Downloading from central: ... —— Maven 正在把 Javalin、Jetty、Logback 以及它们的依赖下载到 ~/.m2/repository。 这些下载只发生一次，之后换项目也能直接复用。 最后看到 BUILD SUCCESS 就对了。

然后运行它：

mvn -q compile exec:java

Javalin 已就位：io.javalin.Javalin

-q（quiet）让 Maven 少打印它自己的日志，只留你程序的输出。 这个组合命令（先编译、再运行）后面几章会一直用。

看清楚自己到底装了什么

原书用 pip freeze 查看虚拟环境里实际装了哪些包。 Maven 的对应命令是 dependency:tree，而且它更有信息量 —— 它会画出 “谁把谁带进来的”： 

mvn -q dependency:tree

com.example:javalinky:jar:1.0-SNAPSHOT
+- io.javalin:javalin:jar:7.2.3:compile
|  +- org.eclipse.jetty:jetty-server:jar:12.0.x:compile
|  +- org.eclipse.jetty.ee10:jetty-ee10-servlet:jar:12.0.x:compile
|  +- org.eclipse.jetty.websocket:jetty-websocket-jetty-server:...:compile
|  \- org.slf4j:slf4j-api:jar:2.0.x:compile
\- ch.qos.logback:logback-classic:jar:1.5.20:compile
   \- ch.qos.logback:logback-core:jar:1.5.20:compile

你声明了 2 个依赖，实际得到 8 个 jar —— 多出来的叫传递依赖（transitive dependency）。 slf4j-api 是 Javalin 带进来的，Jetty 也是。 这棵树在排查“为什么同一个类有两个版本”的问题时非常有用。

💡 两个很实用的 Maven 小命令
# 有哪些依赖可以升级？（相当于 pip list --outdated）
mvn versions:display-dependency-updates

# 把依赖全部打到一个目录，看看它们一共多大
mvn dependency:copy-dependencies -DoutputDirectory=target/libs && du -sh target/libs

💡 开发时的“自动重启”

Flask 有 FLASK_DEBUG=1 带来的自动重载。Javalin 没有内置这个功能，但有两条路：

  • IDE 的热交换：以 Debug 模式启动，改了方法体之后保存，IntelliJ 会把新字节码换进正在运行的 JVM（Build → Build Project，或开启 “Build project automatically”）。改方法体够用，加字段/改签名还是要重启。
  • 模板不需要重启：第 3 章会配置 JTE 从目录加载模板，改 .jte 文件刷新页面就生效。页面调整占了开发时间的大头，所以这条最实用。

重启一个 Javalin 应用通常不到一秒，所以实践中没有想象的那么麻烦。

动手练习

  1. 执行 mvn -q dependency:tree，找出 slf4j-api 是被谁带进来的。 然后把 logback-classic 这条依赖临时注释掉，重新 mvn compile exec:java， 看看控制台多出了什么警告 —— 这就是“只有日志门面、没有日志实现”的症状。
  2. 把 pom.xml 里的 javalin.version 改成 6.7.0，执行 mvn -q dependency:tree， 对比依赖树的差异（提示：Javalin 6 用的是 Jetty 11，包名是 javax.servlet）。改完记得改回 7.2.3。
  3. 执行 mvn clean，观察 target/ 目录消失；再 mvn compile， 到 target/classes 里找到编译出来的 App.class。
  4. 把 maven.compiler.release 改成 17，然后在 App.java 里写一个 record Point(int x, int y) {}，再改成 11。观察报错信息 —— 体会一下这个属性到底在控制什么。
