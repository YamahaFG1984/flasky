模板

上一章我们把 HTML 字符串拼在 Java 代码里，这显然不是长久之计 —— 而且还留了个 XSS 漏洞。 这一章引入模板引擎 JTE，把“页面长什么样”从“业务怎么跑”里拆出去； 顺便把 Bootstrap、自定义错误页、静态文件和时间本地化都搞定。

为什么需要模板

原书这一章开头说得很清楚：视图函数其实背着两个完全独立的职责。 以“用户注册”为例：

模板就是一个带占位符的响应文本；把占位符换成真实数据、得到最终字符串的过程叫渲染。 Flask 用 Jinja2 渲染模板，本教程用 JTE（Java Template Engine）。

为什么是 JTE：编译期检查

Java 有一堆模板引擎：Thymeleaf、FreeMarker、Velocity、Mustache、Pebble…… Javalin 的 javalin-rendering-* 系列都支持。 （顺便说一句，Pebble 的语法几乎就是 Jinja2 的 Java 版， 如果你想要和原书一模一样的 {% if %} / {{ }} 写法，它是最省心的选择。）

但本教程选 JTE，因为它干了一件别的引擎不做的事： 把每个模板编译成一个真正的 Java 类。

加依赖

<properties>
  <!-- ... -->
  <jte.version>3.2.4</jte.version>
</properties>

<dependencies>
  <!-- ... -->

  <!-- Javalin 与 JTE 的胶水层：提供 JavalinJte -->
  <dependency>
    <groupId>io.javalin</groupId>
    <artifactId>javalin-rendering-jte</artifactId>
    <version>${javalin.version}</version>
  </dependency>

  <!-- JTE 本体（含运行时编译器，开发期热加载需要它） -->
  <dependency>
    <groupId>gg.jte</groupId>
    <artifactId>jte</artifactId>
    <version>${jte.version}</version>
  </dependency>
</dependencies>

注册模板引擎

import io.javalin.Javalin;
import io.javalin.rendering.template.JavalinJte;

Javalin.create(config -> {
    // directoryTemplateEngine() 从 src/main/jte 目录读模板：
    // 改 .jte 文件，刷新浏览器就生效，不用重启应用
    config.fileRenderer(new JavalinJte(JavalinJte.Companion.directoryTemplateEngine()));

    // ...
}).start(7070);
ⓘ 开发模式 vs 生产模式

new JavalinJte()（不传参）从 classpath 加载已经预编译好的模板类， 启动快、没有运行时编译器开销 —— 这是生产环境该用的。 预编译由 jte-maven-plugin 在 mvn package 时完成，第 17 章会配。

JavalinJte.Companion.directoryTemplateEngine() 从目录读源文件、运行时编译，支持热加载 —— 开发时用这个。 第 7 章我们会按环境自动切换。

⚠ 那个 .Companion. 不是笔误

Javalin 本身是用 Kotlin 写的。Kotlin 的静态工厂方法一般定义在 companion object 里；这东西编译成字节码后并不是 Java 的 static 方法，而是一个名叫 Companion 的静态嵌套对象的实例方法。 Kotlin 侧写 JavalinJte.directoryTemplateEngine() 就行， Java 侧必须多写一截 .Companion： 

// ❌ 编译不过：cannot find symbol: method directoryTemplateEngine()
JavalinJte.directoryTemplateEngine()

// ✅ Java 侧的正确写法
JavalinJte.Companion.directoryTemplateEngine()

只有标了 @JvmStatic 的成员才能省掉它，而这个方法没标。 后面凡是调 Javalin 类的“静态工厂方法”而找不到符号时，先试试加 .Companion。

⚠ 从这一章起，运行命令要从 exec:java 换成 exec:exec

把上面那行加进 App.java、再照第 1 章的 mvn -q compile exec:java 启动， 会在第一次渲染模板时炸掉： 

java.lang.NoClassDefFoundError: gg/jte/Content

依赖明明在 pom.xml 里，为什么找不到？因为 exec:java 是在 Maven 自己的 JVM 里、用一个自建的类加载器跑你的 main 方法。 而 directoryTemplateEngine() 是运行时把 .jte 编译成 Java 类、 再用 另一个 URLClassLoader 装进来的 —— 那个加载器的父级是 系统类加载器，而系统类加载器里只有 Maven 的东西，没有你的 gg.jte.*。 于是模板类加载到一半找不到父类。

解决办法不是调类加载器，而是别在 Maven 的 JVM 里跑： exec:exec 会 fork 一个真正独立的 java 进程， classpath 由命令行给全，一切照常。在 pom.xml 里把插件配置换成： 

<plugin>
  <groupId>org.codehaus.mojo</groupId>
  <artifactId>exec-maven-plugin</artifactId>
  <version>3.5.0</version>
  <configuration>
    <executable>java</executable>
    <!-- %classpath 由插件展开成完整的 classpath -->
    <commandlineArgs>-classpath %classpath com.example.javalinky.App</commandlineArgs>
  </configuration>
</plugin>

以后启动一律是： 

mvn -q compile exec:exec

注意用 <commandlineArgs> 而不是 <arguments><classpath/>。 后者只有 exec:exec 认得；一旦写进插件级的 <configuration>， 连带 exec:java 也会去解析它，然后报 Unable to parse configuration ... parameter arguments。 用 commandlineArgs 就不会互相干扰。

第一个模板

模板放在 src/main/jte/，扩展名 .jte。先把上一章的两个页面搬过去： 

<h1>Hello World!</h1>

@param String name

<h1>Hello, ${name}!</h1>

@param String name 是 JTE 和 Jinja2 最大的不同： 模板必须声明它需要什么数据，以及类型。 这行声明会变成生成类的方法参数 —— 所以少传、多传、传错类型都会编译失败。 

import java.util.Map;

config.routes.get("/", ctx -> ctx.render("index.jte"));

config.routes.get("/user/{name}", ctx ->
    ctx.render("user.jte", Map.of("name", ctx.pathParam("name"))));

ctx.render(模板路径, 模型) 里的“模型”是一个 Map<String, Object>， 键名必须和模板里 @param 的参数名对上。

Flask
@app.route('/user/<name>')
def user(name):
    return render_template('user.html', name=name)
Javalin
config.routes.get("/user/{name}", ctx ->
    ctx.render("user.jte",
        Map.of("name", ctx.pathParam("name"))));
⚑
原书检查点：本节对应原书 git checkout 3a。
⚠ Map.of() 不允许 null 值

Map.of("name", null) 会抛 NullPointerException。 模型里可能有 null 的时候用 HashMap，或者更好的办法 —— 定义一个页面记录类（下一节马上讲），这是本教程推荐的做法。

用 record 当“页面模型”

Map 能用，但它丢掉了 JTE 最大的优势：类型安全。 一旦页面需要五六个变量，推荐换成 Java 21 的 record： 

package com.example.javalinky.web;

public record UserPage(String name, int visits) {}

@import com.example.javalinky.web.UserPage
@param UserPage page

<h1>Hello, ${page.name()}!</h1>
<p>你是第 ${page.visits()} 次来了。</p>

config.routes.get("/user/{name}", ctx ->
    ctx.render("user.jte", Map.of("page", new UserPage(ctx.pathParam("name"), 3))));
💡 为什么这样更好
  • 模板里写 page.nmae() → 编译失败，而不是页面上出现空白。
  • 给 record 加字段，IDE 会提示所有用到它的模板。
  • 处理器的返回数据有了明确的“契约”，看代码就知道这个页面需要什么。

后面章节的所有页面都用这个模式。record 一行就能定义，成本极低。

JTE 语法速查

对照原书的 Jinja2 语法表，下面是一一对应的清单：

要做的事Jinja2JTE
输出变量{{ name }}${name}
输出不转义的 HTML{{ html|safe }}$unsafe{html}
条件{% if x %}…{% else %}…{% endif %}@if(x)…@else…@endif
多分支{% elif x %}@elseif(x)
循环{% for p in posts %}…{% endfor %}@for(Post p : posts)…@endfor
空列表时的内容需要额外 {% if %}@for(…)…@else…@endfor
注释{# … #}<%-- … --%>
局部变量{% set x = … %}!{var x = …;}
引入其他模板{% include 'x.html' %}@template.x()
宏 / 可复用片段{% macro %} + {% import %}就是一个普通模板 + @template.路径.名字(参数)
模板继承{% extends %} + {% block %}@param Content content + @`…`（下一节）
过滤器{{ s|upper }}直接调 Java 方法：${s.toUpperCase()}

注意最后一行：JTE 没有“过滤器”这个概念，因为你可以直接在模板里写 Java 表达式。 这既是优点（不用学一套新的过滤器名字）也是风险（容易把业务逻辑写进模板）。 规矩是：模板里只做格式化，任何需要判断“业务上该不该”的事都放回 Java。

自动转义：上一章那个漏洞

上一章我们留了个 XSS 漏洞。现在用模板重写之后，试着访问： 

http://localhost:7070/user/<script>alert('xss')</script>

页面上会老老实实显示这串文字，没有弹窗。查看网页源码会发现 JTE 输出的是：

<h1>Hello, &lt;script&gt;alert('xss')&lt;/script&gt;!</h1>

JTE 的转义比“统一替换几个字符”更聪明：它在编译模板时看得懂 HTML 结构， 所以能根据 ${} 所在的位置选择正确的转义规则：

⚠ $unsafe{} 的使用纪律

第 11 章我们会让用户用 Markdown 写文章，渲染出来的 HTML 必须用 $unsafe{} 输出 （否则用户看到的是 &lt;p&gt; 这种东西）。

那时的安全保证不来自模板，而来自“写入数据库之前已经用 OWASP HTML Sanitizer 清洗过标签白名单”。 规矩是：$unsafe{} 输出的内容，必须是服务端自己清洗过的。 用户直接输入的字符串永远不要用 $unsafe{}。

布局：JTE 版的“模板继承”

原书用 Jinja2 的 {% extends %} + {% block %} 做模板继承： 父模板定义骨架，留出几个“洞”，子模板填洞。

JTE 把这件事反过来：没有“继承”，只有“函数调用”。 布局是一个接收 Content 参数的普通模板，页面调用它并把自己的内容作为参数传进去。

组合的好处是：一个页面可以往布局里塞多个块（内容、侧栏、页脚额外脚本）， 而且可以嵌套调用，没有“单继承”限制。

💡 少写点样板：一个 render 小助手

每个处理器都手写 Map.of("layout", ...) 很啰嗦。 加一个工具方法，后面所有章节都用它： 

package com.example.javalinky.web;

import io.javalin.http.Context;
import java.util.HashMap;
import java.util.Map;

public final class View {

    /** 渲染页面，自动补上 layout。pairs 是 "键", 值, "键", 值 … */
    public static void render(Context ctx, String template, String title, Object... pairs) {
        Map<String, Object> model = new HashMap<>();
        model.put("layout", Layout.of(title));
        for (int i = 0; i < pairs.length; i += 2) {
            model.put((String) pairs[i], pairs[i + 1]);   // HashMap 允许 null 值
        }
        ctx.render(template, model);
    }

    private View() {}
}

config.routes.get("/user/{name}", ctx -> {
    String name = ctx.pathParam("name");
    View.render(ctx, "user.jte", name, "page", new UserPage(name, 3));
});
⚑
原书检查点：本节对应原书 git checkout 3b / 3c（Bootstrap 集成 + 二级基础模板）。

Bootstrap：客户端的事，服务端只管引用

原书用 Flask-Bootstrap 扩展，它提供一个 bootstrap/base.html 让你继承。 Javalin 没有对应扩展，也不需要 —— 如原书所说，Bootstrap 是纯客户端框架，服务端要做的只是在 HTML 里引用它的 CSS 和 JS。 上面那个布局模板已经做完了这件事。

两种引用方式：

CDN（最简单，本教程用这个）
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/
  bootstrap@5.3.3/dist/css/bootstrap.min.css">
WebJars（打进 jar，离线可用）
<dependency>
  <groupId>org.webjars.npm</groupId>
  <artifactId>bootstrap</artifactId>
  <version>5.3.3</version>
</dependency>

用 WebJars 的话还要在配置里打开它，之后文件就能从 /webjars/... 访问：

config.staticFiles.enableWebjars();
// <link rel="stylesheet" href="/webjars/bootstrap/5.3.3/dist/css/bootstrap.min.css">
ⓘ WebJars 是什么

就是把 npm 上的前端包重新打成 Maven 依赖。好处：前端资源跟着后端一起版本化、一起打包， 内网部署不依赖外网 CDN。缺点：版本常常落后 npm 几天。 本教程为了让代码片段短一点用 CDN，生产项目建议用 WebJars。

静态文件

CSS、JS、图片这些不需要渲染的文件叫静态文件。 Flask 自动把 static/ 目录映射到 /static/<filename>； Javalin 要你显式声明（但更灵活）： 

import io.javalin.http.staticfiles.Location;

Javalin.create(config -> {
    config.staticFiles.add(staticFiles -> {
        staticFiles.directory = "/public";          // classpath 里的目录
        staticFiles.location = Location.CLASSPATH;  // 从 jar 里读（部署友好）
        staticFiles.hostedPath = "/";               // 对外的 URL 前缀
    });
    // ...
});

对应的文件放在 src/main/resources/public/：

src/main/resources/public/
├── favicon.ico
├── css/
│   └── app.css
└── js/
    └── app.js

于是 src/main/resources/public/css/app.css 的访问路径就是 /css/app.css。

// 也可以挂到子路径下，更接近 Flask 的 /static/ 习惯
config.staticFiles.add(f -> {
    f.directory = "/public";
    f.location = Location.CLASSPATH;
    f.hostedPath = "/static";
});
ⓘ 静态文件的匹配时机

Javalin 的查找顺序是：先 before 钩子 → 再你注册的路由 → 都没匹配上才找静态文件 → 最后 404。 所以你自己的 get("/css/app.css", ...) 会优先于同名静态文件 —— 一般不会冲突，但知道这个顺序有助于排查问题。

给应用加一点自定义样式（原书也有 styles.css）：

.profile-thumbnail { width: 48px; height: 48px; }
.post-body { word-break: break-word; }
.post-list { list-style: none; padding-left: 0; }
.post-list > li { border-bottom: 1px solid var(--bs-border-color); padding: 14px 0; }
⚑
原书检查点：本节对应原书 git checkout 3d（favicon 与静态文件）。

自定义错误页

默认的 404 现在看起来和应用其他页面完全不搭。 Javalin 用 config.routes.error(状态码, ...) 来定制， 而且可以按内容类型分别处理 —— 这一点比 Flask 方便， 原书为此在错误处理函数里手写了 request.accept_mimetypes 的判断（第 14 章才解决）。 

Javalin.create(config -> {
    // 浏览器来的请求 → 渲染好看的 HTML 页面
    config.routes.error(404, "html", ctx ->
        View.render(ctx, "error/404.jte", "页面不存在"));
    config.routes.error(500, "html", ctx ->
        View.render(ctx, "error/500.jte", "服务器错误"));
    config.routes.error(403, "html", ctx ->
        View.render(ctx, "error/403.jte", "没有权限"));

    // API 客户端（Accept: application/json）→ 走 Javalin 默认的 JSON 错误体
    // 不用写任何代码，第 2 章的 NotFoundResponse 已经处理好了
});

@import com.example.javalinky.web.Layout

@param Layout layout

@template.layout.base(layout = layout, content = @`
    <div class="text-center py-5">
        <h1 class="display-1 text-secondary">404</h1>
        <p class="lead">这个页面不存在。</p>
        <a class="btn btn-primary" href="/">回首页</a>
    </div>
`)

error/500.jte 和 error/403.jte 照着改文字即可。 注意 error/404.jte 这个路径 —— JTE 用目录当包名， 所以模板调用写成 @template.error.somePart()（如果需要的话）。

⚠ 500 页面本身不能出错

500 错误页在“应用已经出问题”的情况下渲染。如果这个模板依赖数据库查询（比如显示当前用户）， 它很可能跟着一起失败，用户会看到一片空白。 错误页模板应该只用最简单、不会失败的数据。

链接：没有 url_for 怎么办

原书强调不要在模板里硬写 URL，要用 url_for('main.user', username=u)， 这样改路由时链接不会断。

Javalin 没有 url_for —— 因为 Javalin 的路由没有“端点名”，路由就是路径本身。 但原书想解决的问题是真的，Java 的解法是把路径集中到一个类里，用常量和静态方法。 好处是：改路径时编译器会帮你找出所有引用点，这比 Flask 的运行时解析更安全。 

package com.example.javalinky.web;

import java.net.URLEncoder;
import java.nio.charset.StandardCharsets;

/** 全站 URL 的唯一来源。相当于 Flask 的 url_for。 */
public final class Routes {

    public static final String INDEX = "/";
    public static final String LOGIN = "/auth/login";
    public static final String LOGOUT = "/auth/logout";
    public static final String REGISTER = "/auth/register";
    public static final String EDIT_PROFILE = "/edit-profile";

    public static String user(String username) {
        return "/user/" + enc(username);
    }

    public static String post(long id) {
        return "/post/" + id;
    }

    public static String post(long id, int page) {
        return "/post/" + id + "?page=" + page;
    }

    public static String editPost(long id) {
        return "/edit/" + id;
    }

    public static String follow(String username) {
        return "/follow/" + enc(username);
    }

    /** 绝对 URL：邮件里的链接必须用这个（第 6 章） */
    public static String absolute(String base, String path) {
        return base + path;
    }

    private static String enc(String s) {
        return URLEncoder.encode(s, StandardCharsets.UTF_8);
    }

    private Routes() {}
}

@import com.example.javalinky.web.Routes

<a href="${Routes.user(post.authorUsername())}">${post.authorUsername()}</a>
<a href="${Routes.LOGIN}">登录</a>
💡 相对 URL 还是绝对 URL

和原书的结论一样：站内链接用相对路径（/user/dave）， 要离开浏览器的链接用绝对 URL（https://example.com/auth/confirm/xxx）。 后者只有一个场景 —— 邮件。第 6 章会把站点基地址放进配置，由 Routes.absolute() 拼接。

日期和时间的本地化

原书用 Flask-Moment（Moment.js 的封装）解决这个问题，思路是： 服务端只存 UTC，把时间戳发给浏览器，让浏览器用用户本地时区和语言来显示。 这个思路完全正确，但今天不再需要 Moment.js —— 浏览器原生就能干。

服务端：永远用 Instant

import java.time.Instant;

Instant now = Instant.now();            // 当前时刻，UTC，没有时区
String iso = now.toString();            // "2026-10-21T08:30:00.123Z"
☀ Java 时间类型怎么选
类型含义用在哪
Instant时间轴上的一个点（UTC 纪元毫秒）本教程全部时间戳都用它
LocalDate只有年月日，没有时刻生日、账单周期
LocalDateTime有日期有时刻，但没有时区 —— 含义模糊尽量别用来存时间戳
ZonedDateTime带时区的时刻“每天北京时间 9 点发送”这类业务规则

一句话：“某件事发生的时刻”用 Instant， 其他类型只在业务真的关心日历和时区时才出现。

模板：输出一个可被脚本接管的 <time>

做一个可复用的模板片段（相当于 Jinja2 的 macro）：

@import java.time.Instant

@param Instant at
@param boolean relative = true

<time datetime="${at.toString()}"
      data-style="${relative ? "relative" : "absolute"}">
    ${at.toString()}
</time>

<time> 标签里先放 ISO 字符串作为兜底 —— 即使用户禁用了 JavaScript，也能看到一个（不好看但正确的）时间。 这是渐进增强的做法。 

<%-- 在任何页面里这样用 --%>
<div class="text-muted small">
    发布于 @template.tag.timeago(at = post.timestamp())
</div>

<%-- 要绝对时间就传 relative = false --%>
注册于 @template.tag.timeago(at = user.memberSince(), relative = false)

浏览器：用 Intl 把它换成人话

// 把所有 <time datetime="..."> 换成本地化的显示
(function () {
  const rtf = new Intl.RelativeTimeFormat(navigator.language, { numeric: 'auto' });
  const abs = new Intl.DateTimeFormat(navigator.language, {
    dateStyle: 'long', timeStyle: 'short'
  });

  const UNITS = [
    ['year',   31536000],
    ['month',  2592000],
    ['week',   604800],
    ['day',    86400],
    ['hour',   3600],
    ['minute', 60],
    ['second', 1]
  ];

  function relative(date) {
    const diffSec = (date - Date.now()) / 1000;          // 过去是负数
    for (const [unit, secs] of UNITS) {
      if (Math.abs(diffSec) >= secs || unit === 'second') {
        return rtf.format(Math.round(diffSec / secs), unit);
      }
    }
  }

  function upgrade(el) {
    const date = new Date(el.getAttribute('datetime'));
    if (isNaN(date)) return;
    el.title = abs.format(date);                          // 鼠标悬停看精确时间
    el.textContent = el.dataset.style === 'absolute'
      ? abs.format(date)
      : relative(date);
  }

  document.querySelectorAll('time[datetime]').forEach(upgrade);

  // 每分钟刷新一次相对时间（“3 分钟前” → “4 分钟前”）
  setInterval(function () {
    document.querySelectorAll('time[datetime][data-style="relative"]').forEach(upgrade);
  }, 60000);
})();

这段 30 行的脚本替代了原书的 Flask-Moment + Moment.js + jQuery （加起来约 70 KB 的下载量）。 Intl.RelativeTimeFormat 会自动按浏览器语言输出“3 分钟前”/“3 minutes ago”/“hace 3 minutos”。

package com.example.javalinky;

import com.example.javalinky.web.UserPage;
import com.example.javalinky.web.View;
import io.javalin.Javalin;
import io.javalin.http.staticfiles.Location;
import io.javalin.rendering.template.JavalinJte;

public class App {

    public static void main(String[] args) {
        int port = Integer.parseInt(System.getenv().getOrDefault("PORT", "7070"));

        Javalin.create(config -> {

            // --- 模板引擎 ---
            config.fileRenderer(new JavalinJte(JavalinJte.Companion.directoryTemplateEngine()));

            // --- 静态文件 ---
            config.staticFiles.add(f -> {
                f.directory = "/public";
                f.location = Location.CLASSPATH;
                f.hostedPath = "/";
            });

            // --- 开发期辅助 ---
            config.bundledPlugins.enableDevLogging();
            config.bundledPlugins.enableRouteOverview("/routes");

            // --- 自定义错误页 ---
            config.routes.error(404, "html", ctx ->
                View.render(ctx, "error/404.jte", "页面不存在"));
            config.routes.error(403, "html", ctx ->
                View.render(ctx, "error/403.jte", "没有权限"));
            config.routes.error(500, "html", ctx ->
                View.render(ctx, "error/500.jte", "服务器错误"));

            // --- 路由 ---
            config.routes.get("/", ctx ->
                View.render(ctx, "index.jte", "首页"));

            config.routes.get("/user/{name}", ctx -> {
                String name = ctx.pathParam("name");
                View.render(ctx, "user.jte", name, "page", new UserPage(name, 3));
            });

        }).start(port);
    }
}

动手练习

  1. 在 user.jte 里故意把 page.name() 写成 page.nmae()， 然后 mvn compile。读一下报错信息 —— 它会告诉你模板的哪一行。 这就是“编译期模板检查”的价值。
  2. 访问 /user/<b>粗体</b>，确认标签被转义成文字显示。 然后把模板里的 ${page.name()} 改成 $unsafe{page.name()}，再访问一次， 观察差别。改完记得改回去。
  3. 做一个 tag/alert.jte 片段，参数是 String level（info/warning/danger）和 Content body，渲染成 Bootstrap 的 <div class="alert alert-xxx">。 然后在首页调用它两次，传不同的 level。 （提示：内容块参数写成 body = @`…`）
  4. 给布局加一个可选的 Content sidebar = null 参数： 传了就渲染成右侧 4 栏，不传就让主内容占满 12 栏。在 user.jte 里用上它。
  5. 访问一个不存在的路径，确认看到的是你的 404 页面。 然后用 curl -H "Accept: application/json" localhost:7070/nope， 确认 API 客户端拿到的是 JSON。
  6. 把 timeago.jte 用在首页：显示“服务器启动于 ⟨相对时间⟩”。 把浏览器语言切成英文再刷新，看看文字是否跟着变。
