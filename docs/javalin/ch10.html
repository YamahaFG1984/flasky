第 10 章

用户资料

现在用户只有邮箱和用户名，太干了。这一章给每个人加上个人资料页： 真名、所在地、自我介绍、注册时间、最后活跃时间和头像； 再做两套编辑器 —— 一套给用户自己，一套给管理员。

本章目标

  • 给 User 加资料字段并写好迁移
  • 做出资料页，并理解“页面模型 record”的价值
  • 实现用户级和管理员级两套编辑器，看清它们的权限差异
  • 接上 Gravatar 头像，理解 URL 是怎么拼出来的
  • 认识“最后活跃时间”带来的写放大问题

ⓘ 为什么这些字段都可以为 null

name、location、aboutMe 都没有 nullable = false—— 用户刚注册时什么都没填，强制非空只会逼你用空字符串当"没填"，更乱。

但这意味着模板里必须处理 null。 下面我们用页面模型 record 把 null 统一转成空字符串，让模板干净。

最后活跃时间：一个性能陷阱

第 8 章的 CurrentUser.install() 里有这么一行： 

user.setLastSeen(Instant.now());   // 托管对象，改字段 = 提交时 UPDATE

原书也做了同样的事（current_user.ping()）。 它能工作，但有个代价值得知道： 

/** 最后活跃时间的最小更新间隔 */
private static final Duration PING_INTERVAL = Duration.ofMinutes(5);

public static void install(JavalinConfig config) {
    config.routes.before(ctx -> {
        Long userId = ctx.sessionAttribute(SESSION_KEY);
        if (userId == null) return;

        User user = new UserRepository(Db.em(ctx)).findById(userId).orElse(null);
        if (user == null) { logout(ctx); return; }

        ctx.attribute(CTX_KEY, user);
        ping(user);
    });
}

private static void ping(User user) {
    Instant now = Instant.now();
    Instant last = user.getLastSeen();
    if (last == null || Duration.between(last, now).compareTo(PING_INTERVAL) >= 0) {
        user.setLastSeen(now);
    }
}
💡 还能再优化

更彻底的做法是不写数据库：把 userId → 最后活跃时间 放进 Redis（或一个进程内的 ConcurrentHashMap）， 每隔几分钟批量刷回数据库一次。

但在用户量不大时，上面的 5 分钟节流已经完全够用。 先用简单方案，有数据证明它成了瓶颈再优化—— 第 16 章会讲怎么拿到这个数据。

资料页

这是本教程第一个“数据比较多”的页面，正好用它说明一个重要的做法： 不要把实体直接丢给模板，先转成页面模型。 

package com.example.javalinky.web.page;

import com.example.javalinky.model.User;
import com.example.javalinky.util.Gravatar;
import java.time.Instant;

public record UserProfilePage(
    long id,
    String username,
    String name,            // 保证非 null，没填就是空串
    String location,
    String aboutMe,
    String email,           // 只有管理员能看到，否则是空串
    Instant memberSince,
    Instant lastSeen,
    String avatarUrl,
    long postCount,
    long commentCount,
    long followerCount,
    long followingCount,
    boolean isSelf,         // 看的是自己的主页吗
    boolean canFollow,      // 当前访客能不能关注这个人
    boolean isFollowing,    // 当前访客已经关注了吗
    boolean followsYou      // 这个人关注了当前访客吗
) {

    public static UserProfilePage of(User user, boolean viewerIsAdmin, boolean isSelf,
                                     long postCount, long commentCount,
                                     long followerCount, long followingCount,
                                     boolean canFollow, boolean isFollowing,
                                     boolean followsYou) {
        return new UserProfilePage(
            user.getId(),
            user.getUsername(),
            orEmpty(user.getName()),
            orEmpty(user.getLocation()),
            orEmpty(user.getAboutMe()),
            viewerIsAdmin ? user.getEmail() : "",
            user.getMemberSince(),
            user.getLastSeen(),
            Gravatar.url(user.avatarHash(), 256),
            postCount, commentCount, followerCount, followingCount,
            isSelf, canFollow, isFollowing, followsYou);
    }

    public boolean hasName()     { return !name.isEmpty(); }
    public boolean hasLocation() { return !location.isEmpty(); }
    public boolean hasAboutMe()  { return !aboutMe.isEmpty(); }
    public boolean hasEmail()    { return !email.isEmpty(); }

    private static String orEmpty(String s) {
        return s == null ? "" : s;
    }
}

private void userProfile(Context ctx) {
    var users = services.users(ctx);
    User user = users.findByUsername(ctx.pathParam("username"))
        .orElseThrow(() -> new NotFoundResponse("没有这个用户"));

    User viewer = CurrentUser.get(ctx);
    var posts = services.postRepo(ctx);

    var page = UserProfilePage.of(
        user,
        viewer != null && viewer.isAdministrator(),
        viewer != null && viewer.getId().equals(user.getId()),
        posts.countByAuthor(user),
        services.commentRepo(ctx).countByAuthor(user),
        0, 0,                       // 关注数，第 12 章填上
        viewer != null && viewer.can(Permission.FOLLOW)
            && !viewer.getId().equals(user.getId()),
        false, false);              // 关注状态，第 12 章填上

    View.render(ctx, "user.jte", user.getUsername(), "page", page);
}

两级资料编辑器

用户级

package com.example.javalinky.web.form;

import jakarta.validation.constraints.Size;

public record EditProfileForm(
    @Size(max = 64, message = "真名最长 64 个字符") String name,
    @Size(max = 64, message = "所在地最长 64 个字符") String location,
    @Size(max = 2000, message = "自我介绍最长 2000 个字符") String aboutMe
) {}

private void editProfileForm(Context ctx) {
    User user = CurrentUser.require(ctx);
    // GET 时把当前值回填进表单
    var values = new HashMap<String, String>();
    values.put("name", orEmpty(user.getName()));
    values.put("location", orEmpty(user.getLocation()));
    values.put("aboutMe", orEmpty(user.getAboutMe()));

    View.render(ctx, "edit_profile.jte", "编辑资料",
                "form", new FormView(values, Map.of()),
                "admin", false,
                "targetUser", null);
}

private void editProfile(Context ctx) {
    User user = CurrentUser.require(ctx);
    var form = new EditProfileForm(
        ctx.formParam("name"),
        ctx.formParam("location"),
        ctx.formParam("aboutMe"));

    var errors = Forms.validate(form);
    if (!errors.isEmpty()) {
        View.render(ctx, "edit_profile.jte", "编辑资料",
                    "form", new FormView(formValues(form), errors),
                    "admin", false, "targetUser", null);
        return;
    }

    user.setName(blankToNull(form.name()));
    user.setLocation(blankToNull(form.location()));
    user.setAboutMe(blankToNull(form.aboutMe()));
    // 不需要 save() —— 托管对象，事务提交时自动 UPDATE

    Flash.success(ctx, "资料已更新。");
    ctx.redirect(Routes.user(user.getUsername()));
}

/** 空字符串存成 null，保持"没填"的语义统一 */
private static String blankToNull(String s) {
    return (s == null || s.isBlank()) ? null : s.trim();
}

管理员级

package com.example.javalinky.web.form;

import jakarta.validation.constraints.*;

public record AdminEditProfileForm(
    @NotBlank(message = "请填写邮箱")
    @Size(max = 64) @Email(message = "邮箱格式不正确")
    String email,

    @NotBlank(message = "请填写用户名")
    @Size(max = 64)
    @Pattern(regexp = "^[A-Za-z][A-Za-z0-9_.]*$",
             message = "用户名必须以字母开头，只能包含字母、数字、点和下划线")
    String username,

    boolean confirmed,

    @NotNull(message = "请选择角色")
    Long roleId,

    @Size(max = 64) String name,
    @Size(max = 64) String location,
    @Size(max = 2000) String aboutMe
) {}

private void adminEditProfile(Context ctx) {
    long targetId = ctx.pathParamAsClass("id", Long.class).get();
    var users = services.users(ctx);
    var roles = services.roles(ctx);

    User target = users.findById(targetId)
        .orElseThrow(() -> new NotFoundResponse("没有这个用户"));

    var form = new AdminEditProfileForm(
        ctx.formParam("email"),
        ctx.formParam("username"),
        ctx.formParam("confirmed") != null,
        ctx.formParamAsClass("roleId", Long.class).allowNullable().get(),
        ctx.formParam("name"),
        ctx.formParam("location"),
        ctx.formParam("aboutMe"));

    var errors = new LinkedHashMap<String, List<String>>(Forms.validate(form));

    // 唯一性检查：排除"自己"（原书的 validate_email 也是这个逻辑）
    String email = form.email() == null ? "" : form.email().toLowerCase();
    if (!errors.containsKey("email")
            && !email.equalsIgnoreCase(target.getEmail())
            && users.emailExists(email)) {
        errors.put("email", List.of("这个邮箱已被其他账号使用"));
    }
    if (!errors.containsKey("username")
            && !form.username().equals(target.getUsername())
            && users.usernameExists(form.username())) {
        errors.put("username", List.of("这个用户名已被占用"));
    }

    if (!errors.isEmpty()) {
        renderAdminForm(ctx, target, errors, roles.findAll());
        return;
    }

    boolean emailChanged = !email.equalsIgnoreCase(target.getEmail());
    target.setEmail(email);
    target.setUsername(form.username());
    target.setConfirmed(form.confirmed());
    target.setRole(roles.findById(form.roleId())
        .orElseThrow(() -> new BadRequestResponse("角色不存在")));
    target.setName(blankToNull(form.name()));
    target.setLocation(blankToNull(form.location()));
    target.setAboutMe(blankToNull(form.aboutMe()));

    if (emailChanged) {
        target.setAvatarHash(null);   // 头像哈希要按新邮箱重算
    }

    Flash.success(ctx, "已更新 " + target.getUsername() + " 的资料。");
    ctx.redirect(Routes.user(target.getUsername()));
}
⚠ 改用户名会让旧链接失效

我们的资料页 URL 是 /user/{username}。 管理员一改用户名，所有指向旧地址的链接（包括搜索引擎收录的）就全部 404 了。

真实项目里的常见做法：

  • URL 用不可变的 id（/user/42）—— 最稳，但不好看、不好记；
  • 或者 /user/42-john（id + 用户名），只用 id 查询，用户名部分只是装饰；
  • 或者保留一张“旧用户名 → 用户”的表，访问旧地址时 301 重定向。

本教程跟原书保持一致用用户名，但你应该知道这个取舍。

头像：Gravatar

Gravatar（Globally Recognized Avatar）是一个很老但依然好用的服务： 用户在 gravatar.com 上传一次头像，任何网站都能用他的邮箱哈希取到。 好处是我们完全不用处理文件上传、图片裁剪和存储。 

package com.example.javalinky.util;

import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;
import java.util.HexFormat;

public final class Gravatar {

    private static final String BASE = "https://www.gravatar.com/avatar/";

    /** 邮箱 → MD5 哈希（小写、去空格，这是 Gravatar 规定的） */
    public static String hash(String email) {
        if (email == null) return "";
        try {
            byte[] digest = MessageDigest.getInstance("MD5")
                .digest(email.trim().toLowerCase().getBytes(StandardCharsets.UTF_8));
            return HexFormat.of().formatHex(digest);
        } catch (NoSuchAlgorithmException e) {
            throw new IllegalStateException("JVM 居然没有 MD5", e);
        }
    }

    public static String url(String hash, int size) {
        return url(hash, size, "identicon");
    }

    public static String url(String hash, int size, String fallback) {
        return BASE + (hash == null ? "" : hash)
             + "?s=" + size + "&d=" + fallback + "&r=g";
    }

    private Gravatar() {}
}
ⓘ 这里用 MD5 不是安全问题

MD5 作为密码哈希已经被彻底淘汰（第 8 章讲过）。 但这里用它不是为了保密，而是因为Gravatar 的接口规定就是 MD5—— 它只是一个"把邮箱变成固定字符串"的编码方式。

判断"能不能用 MD5"的标准是：你是在防谁？ 防攻击者 → 不能用；只是要一个确定性的标识符 → 没问题。

缓存哈希

一个页面可能显示 20 个用户的头像，每个都算一次 MD5 虽然不贵，但完全没必要 —— 邮箱不变，哈希就不变。原书的做法是把哈希存进 avatar_hash 列： 

/**
 * 取 Gravatar 哈希。没有缓存就算一次并存下来。
 * 第 8 章的"改邮箱"会把这个字段置 null，这里就会重算。
 */
public String avatarHash() {
    if (avatarHash == null || avatarHash.isBlank()) {
        avatarHash = Gravatar.hash(email);
    }
    return avatarHash;
}

public void setAvatarHash(String hash) {
    this.avatarHash = hash;
}
💡 注意这个方法有个“副作用”

avatarHash() 看起来像个 getter，但它会修改字段 —— 而对一个托管实体来说，改字段意味着事务提交时会发 UPDATE。

这正是我们要的（哈希被持久化了，下次不用再算）。 但这也是 Hibernate 容易让人困惑的地方： 调用一个 getter 居然产生了数据库写入。 写这种"惰性初始化"代码时要心里有数。

按尺寸取图

@import com.example.javalinky.model.User
@import com.example.javalinky.util.Gravatar

@param User user
@param int size = 40
@param String cssClass = "rounded"

<img class="${cssClass}"
     src="${Gravatar.url(user.avatarHash(), size)}"
     srcset="${Gravatar.url(user.avatarHash(), size * 2)} 2x"
     width="${size}" height="${size}"
     alt="${user.getUsername()} 的头像"
     loading="lazy">
☀ 三个小细节，但都有用
  • srcset="… 2x"：高清屏取双倍尺寸的图，普通屏不浪费流量。
  • width / height：浏览器在图片加载前就知道占多大空间， 避免页面加载时内容乱跳（CLS）。
  • loading="lazy"：列表里下方的头像滚动到才加载。 列 50 篇文章的首页上，这能省掉几十个请求。
🔎 深入：不想用 Gravatar 怎么办

Gravatar 的问题是：依赖外部服务（挂了你的头像就全没了）、泄露邮箱哈希、国内访问慢。 自己做头像上传的话，需要处理：

  1. 接收上传：ctx.uploadedFile("avatar")， 配 config.jetty.multipartConfig.maxFileSize(2, SizeUnit.MB)。
  2. 校验：不能信 Content-Type（客户端可以乱填）， 要读文件头的魔术字节（PNG 是 89 50 4E 47，JPEG 是 FF D8 FF）。
  3. 处理：用 javax.imageio 或 Thumbnailator 裁剪成正方形并缩放成几档尺寸。 这一步顺便去掉了原图的 EXIF（里面可能有拍照位置）。
  4. 存储：不要存在应用服务器的本地磁盘（第 17 章会讲为什么）—— 用对象存储（S3 / 阿里云 OSS），数据库只存一个 key。
  5. 兜底：没上传的用户显示什么？用用户名首字母 + 按 id 算出的背景色， 几行代码就能生成，而且永远不会挂。

这是一个完整的小项目，很适合当本章的扩展练习。

动手练习

  1. 注册一个账号，填上真名、所在地和自我介绍，访问自己的资料页确认都显示了。 然后清空所有字段再保存，确认页面上那几行整块消失（而不是显示空白行）—— 这是 hasName() 这些方法的作用。
  2. 在自我介绍里输入 <script>alert(1)</script> 保存。 确认页面上显示的是文字而不是弹窗 —— JTE 的自动转义在工作。
  3. 用管理员账号打开别人的管理员编辑页，把他的角色改成"协管员"。 然后用那个账号登录，确认导航栏多出了"协管评论"（第 13 章才有实际页面， 现在至少链接会出现）。
  4. 把 PING_INTERVAL 改成 Duration.ZERO， 打开 hibernate.show_sql，刷新页面几次， 数一数发了多少条 update users。改回 5 分钟再数一次。
  5. 在 JShell 里执行 Gravatar.hash("someone@example.com")， 把结果拼成 URL 在浏览器里打开。 然后把 d=identicon 换成 d=retro 和 d=robohash，看看区别。
  6. 修改自己的邮箱（走 /auth/change-email 的完整流程）， 确认头像变了——验证 avatarHash 被正确重置了。
  7. （进阶）按上面「深入」里的五步，实现自托管的头像上传。 至少做到前三步：接收、校验魔术字节、缩放成 256px 的正方形 PNG。
