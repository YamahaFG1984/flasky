第 2 章

应用的基本结构

这一章你会写出第一个真正能跑的 Javalin 应用，并且理解一个请求从网卡进来、到响应发回去， 中间到底经过了哪些地方。这是整本教程最重要的一章 —— 后面所有内容都是在这个循环上挂东西。

本章目标

  • 会创建、配置、启动一个 Javalin 实例
  • 理解“路由”和“处理器”，会写静态路由和带参数的动态路由
  • 理解 Javalin 的 Context 为什么要显式传参，而 Flask 的 request 像全局变量
  • 掌握请求生命周期的六个钩子：before、beforeMatched、endpoint、afterMatched、error、exception
  • 会设置状态码、响应头、Cookie、重定向，会抛出标准 HTTP 异常

初始化：应用实例

所有 Flask 应用都要先创建一个应用实例 app = Flask(__name__)， Web 服务器把收到的请求都交给这个对象处理。Javalin 完全一样，只是创建方式不同：

Flask 这样写
from flask import Flask
app = Flask(__name__)
Javalin 这样写
import io.javalin.Javalin;

var app = Javalin.create(config -> {
    // 所有配置和路由都写在这里
});

Javalin.create() 接收一个 配置 lambda。 Flask 需要 __name__ 来定位模板和静态文件的位置；Javalin 不需要， 因为它从 classpath 加载资源，而 classpath 已经由 Maven 确定了。

⚠ Javalin 7 的一个重要变化

路由必须在 create() 的配置块里注册，调用 .start() 之后不能再加路由。 你在网上搜到的 Javalin 6 及更早的教程写的是 app.get("/", ...)（在 start 之后）， 那种写法在 Javalin 7 里会抛异常。

Javalin 6（已不适用）
var app = Javalin.create().start(7070);
app.get("/", ctx -> ctx.result("Hi"));
Javalin 7（本教程）
var app = Javalin.create(config -> {
    config.routes.get("/", ctx -> ctx.result("Hi"));
}).start(7070);

这个改动看起来只是挪了个位置，其实挺重要：它保证了“服务器一旦开始接受请求，路由表就是完整且不变的”。 第 7 章我们会看到，它还让“应用工厂”模式变得非常自然。

路由与处理器

浏览器把请求发给服务器，服务器交给 Javalin。Javalin 需要知道每个 URL 该跑哪段代码， 所以它维护了一张 URL → 代码的映射表。一条映射叫一个 路由（route）， 映射到的那段代码叫 处理器（handler）。 

config.routes.get("/", ctx -> ctx.html("<h1>Hello World!</h1>"));

这行代码干了三件事，和 Flask 的 @app.route('/') 装饰器一一对应：

部分含义Flask 里的对应物
getHTTP 方法。还有 post、put、patch、delete、head、optionsmethods=['GET']
"/"路径装饰器的第一个参数
ctx -> ...处理器，一个 Handler 函数式接口的实现视图函数

Handler 接口的方法返回类型是 void —— 这是和 Flask 最直观的差别。 Flask 的视图函数 return 什么，什么就是响应体； Javalin 的处理器不返回任何东西，而是通过 ctx 上的方法设置响应：

Flask：返回值就是响应
@app.route('/')
def index():
    return '<h1>Hello World!</h1>'
Javalin：在 ctx 上设置响应
config.routes.get("/", ctx -> {
    ctx.html("<h1>Hello World!</h1>");
});
ⓘ 为什么 Java 不用装饰器

Python 的装饰器是“把函数当参数传给另一个函数”的语法糖。Java 没有这个语法， 但 Java 8 之后有了 lambda，所以直接把处理器当参数传进去 —— 本质上和 app.add_url_rule('/', 'index', index)（原书提到的 Flask 非装饰器写法）是同一件事。

一个完整的应用

把上一章的 App.java 改成这样：

package com.example.javalinky;

import io.javalin.Javalin;

public class App {
    public static void main(String[] args) {
        Javalin.create(config -> {
            config.routes.get("/", ctx -> ctx.html("<h1>Hello World!</h1>"));
        }).start(7070);
    }
}

💡 端口号与“为什么是 7070”

Flask 开发服务器默认 5000，Javalin 文档习惯用 7070，都只是惯例。 .start() 不传参数时默认是 8080。生产环境一般从环境变量读端口： 

int port = Integer.parseInt(System.getenv().getOrDefault("PORT", "7070"));
app.start(port);

也可以用 .start("127.0.0.1", 7070) 指定绑定的网卡。默认绑定全部网卡（相当于 Flask 的 --host 0.0.0.0），同一局域网内的其他机器可以访问。

动态路由

很多 URL 带可变部分，比如 /user/<你的用户名>。Javalin 有两种语法： 

Javalin.create(config -> {
    config.routes.get("/", ctx -> ctx.html("<h1>Hello World!</h1>"));

    // {name} 不允许包含斜杠
    config.routes.get("/user/{name}", ctx -> {
        ctx.html("<h1>Hello, " + ctx.pathParam("name") + "!</h1>");
    });

    // <path> 允许包含斜杠，适合文件路径这类场景
    config.routes.get("/files/<path>", ctx -> {
        ctx.result("你要的文件是：" + ctx.pathParam("path"));
    });
}).start(7070);

访问 http://localhost:7070/user/Dave 会看到 “Hello, Dave!”。

Javalin匹配Flask 的对应写法
/user/{name}/user/dave，但不匹配 /user/a/b/user/<name>
/files/<path>/files/a/b/c.txt/files/<path:p>
/admin/*任何以 /admin/ 开头的路径，但取不到通配的值—

类型转换：路径参数不只是字符串

Flask 可以写 /user/<int:id>，让框架帮你转成整数并拒绝非数字。 Javalin 的做法是 pathParamAsClass，它返回一个 Validator： 

config.routes.get("/post/{id}", ctx -> {
    // 转不成 int 时，Javalin 自动返回 400 Bad Request + JSON 错误说明
    int id = ctx.pathParamAsClass("id", Integer.class).get();
    ctx.result("文章 #" + id);
});

// 还可以附加检查
config.routes.get("/page/{n}", ctx -> {
    int n = ctx.pathParamAsClass("n", Integer.class)
               .check(v -> v > 0, "页码必须是正整数")
               .get();
    ctx.result("第 " + n + " 页");
});

Validator 是 Javalin 里很核心的一个小工具，第 4 章处理表单、第 14 章处理 JSON 时还会大量用到。

“调试模式”：Javalin 的等价物

Flask 的 FLASK_DEBUG=1 打开两个东西：自动重载和网页版交互式调试器。 Javalin 的情况不一样，值得分开说：

Flask 调试模式提供的Javalin 的对应
改代码自动重启没有内置。用 IDE 的热交换，或者接受“重启只要 0.3 秒”（见第 1 章）
浏览器里的交互式堆栈没有，也不该有。异常堆栈打到控制台日志；IDE 的断点调试比网页调试器强得多
—开发日志：把每个请求的完整头、体、耗时打到控制台
—路由总览：一个页面列出所有已注册的路由
Javalin.create(config -> {
    // 开发期神器：打印每个请求/响应的全部细节
    config.bundledPlugins.enableDevLogging();

    // 访问 /routes 可以看到所有路由的表格
    config.bundledPlugins.enableRouteOverview("/routes");

    config.routes.get("/", ctx -> ctx.html("<h1>Hello World!</h1>"));
}).start(7070);
⚠ 这两个都只能在开发环境开

enableDevLogging() 会把请求体和响应体（可能包含密码、令牌）整段打进日志； enableRouteOverview() 把你的全部 API 结构公开出去。 第 7 章我们会用配置开关把它们关在开发环境里。

命令行参数

原书这一节讲 flask run --host --port 这些选项。 Java 没有一个“框架自带的 CLI”，启动参数就是 main(String[] args) 和环境变量。 这其实更简单，也更容易在容器里配置：

请求-响应循环

现在来看最关键的部分：一个请求进来，到底发生了什么。

线程模型：一个请求一个线程

Jetty 维护一个线程池（默认 250 个线程）。每个进来的请求占用一个线程直到处理完。 这和 Flask 的默认模型类似（WSGI 服务器也是线程/进程池），但有两个实际后果你要记住：

  • 在处理器里阻塞是合法的。查数据库、发 HTTP 请求可以直接同步写，不需要 async/await。 这让 Java Web 代码读起来很顺。
  • 线程数是有限的。如果每个请求都阻塞 3 秒，250 个并发就打满了。 Java 21 的虚拟线程正是为了解决这个：线程变得极其廉价，阻塞不再是问题。 Javalin 一行配置就能开：
Javalin.create(config -> {
    config.concurrency.useVirtualThreads = true;   // Java 21+
    // ...
});
🔎 深入：虚拟线程为什么重要

传统 Java 线程是操作系统线程的包装，每个要占约 1 MB 栈空间，创建开销大，所以必须池化。 虚拟线程由 JVM 自己调度，一个可以只占几百字节，创建上百万个都没问题。 当虚拟线程执行到一个阻塞操作（比如等数据库返回）时，JVM 会把它从底层的 OS 线程上卸下来， 让这个 OS 线程去跑别的虚拟线程。

结果就是：你照常写同步阻塞代码，却能拿到接近异步框架的并发能力。 这也是为什么本教程所有数据库代码都用最朴素的同步写法 —— 在 Java 21 上它已经够快了。

Context：Javalin 没有“上下文全局变量”

这是 Flask 和 Javalin 在设计哲学上最大的一处分歧，值得单独讲。

原书第 2 章花了很长篇幅解释 Flask 的应用上下文和请求上下文： 为什么 request 看起来是全局变量却能在多线程下正确工作， 为什么在请求之外访问它会报 working outside of request context， 为什么往后台线程里传 app 还要手动 with app.app_context()（原书第 6 章发异步邮件时就踩了这个坑）。

Javalin 把这些问题从根上消掉了：没有全局变量，所有东西都从处理器的 ctx 参数上取。

☀ 这个差异会一路影响你的代码风格

因为 ctx 必须显式传递，你会自然而然地不把它往深处传： 在处理器里把需要的数据从 ctx 取出来，调用一个只接收普通参数的方法去干活。 

// 推荐：处理器只负责"取参数 → 调服务 → 设响应"
config.routes.post("/posts", ctx -> {
    String body = ctx.formParam("body");
    long userId = ctx.sessionAttribute("userId");
    Post post = postService.publish(userId, body);   // 不传 ctx！
    ctx.redirect("/post/" + post.getId());
});

这样写出来的 postService 完全不知道 HTTP 的存在，于是能在单元测试里脱离 Web 环境直接测 （第 15 章原书也强调了同样的分层原则）。

读请求：Context 的请求方法

原书用一张表列出了 Flask request 对象的常用属性。 下面是 Javalin Context 的对应清单（按读请求/写响应分开，这里先看读）：

ⓘ attribute() 就是 Flask 的 g

原书提到“在 before_request 里把当前用户塞进 g.user，视图函数再取出来”。 Javalin 完全一样，只是换个名字 —— 第 8 章我们会这样做： 

config.routes.before(ctx -> {
    Long userId = ctx.sessionAttribute("userId");
    ctx.attribute("currentUser", userId == null ? null : users.find(userId));
});

config.routes.get("/", ctx -> {
    User me = ctx.attribute("currentUser");   // 可能是 null
    // ...
});

请求钩子：洋葱模型

有些代码需要在每个请求前后执行：记录日志、认证用户、打开数据库连接、 统计耗时。原书把这类功能叫“请求钩子”，Flask 提供四个装饰器。 Javalin 提供六个挂载点，而且顺序是严格确定的： 

Javalin.create(config -> {
    config.routes.before(ctx       -> { /* ① 每个请求 */ });
    config.routes.beforeMatched(ctx -> { /* ② 只有匹配到路由时 */ });

    config.routes.get("/", ctx     -> { /* ③ 处理器 */ });

    config.routes.afterMatched(ctx -> { /* ④ 匹配过的请求结束后 */ });
    config.routes.after(ctx        -> { /* ⑤ 每个请求结束后，抛异常也跑 */ });

    config.routes.error(404, ctx   -> { /* 状态码是 404 时 */ });
    config.routes.exception(Exception.class, (e, ctx) -> { /* 抛异常时 */ });
});
Javalin何时执行Flask 的对应
before每个请求之前，包括静态文件和最终 404 的请求before_request
beforeMatched确认有路由能处理之后、处理器之前（Flask 没有，要自己判断 request.endpoint）
afterMatched处理器正常结束后after_request
after每个请求最后，即使抛了异常teardown_request
exception(Type, ...)有处理器抛出该类型异常时errorhandler(Exception)
error(code, ...)响应状态码等于 code 时（第 3 章做自定义错误页要用）errorhandler(404)

还可以给钩子限定路径，只在某个前缀下生效 —— 这在做后台管理区的鉴权时很好用：

config.routes.before("/admin/*", ctx -> {
    if (!isAdmin(ctx)) throw new ForbiddenResponse();
});
💡 beforeMatched 是 Javalin 的精髓之一

为什么需要区分 before 和 beforeMatched？考虑“检查登录”这件事：

  • 放在 before 里：favicon.ico、CSS 文件、任何打错的 URL 都会触发检查，浪费且容易误伤。
  • 放在 beforeMatched 里：只有真的要进入某个业务处理器时才检查， 而且此时 ctx.routeRoles() 已经能告诉你“这条路由需要什么权限”。

第 9 章整套权限系统就建立在这一点上。

写响应

Flask 视图函数可以返回字符串、(body, status) 元组、或者 make_response() 造的响应对象。 Javalin 统一通过 ctx 的方法设置，而且可以链式调用：

Context 方法说明
result("文本")设置响应体（纯文本）
html("<h1>..</h1>")设置响应体并把 Content-Type 设为 text/html
json(obj)序列化成 JSON 并设 Content-Type（第 14 章）
render("page.jte", model)渲染模板（第 3 章）
status(201)状态码。默认 200
header("X-Foo", "bar")响应头
contentType("text/csv")Content-Type
cookie("name", "value", maxAge)设置 Cookie
removeCookie("name")删除 Cookie
redirect("/path")重定向（默认 302，可传第二个参数指定状态码）
Flask
@app.route('/')
def index():
    return '<h1>Bad Request</h1>', 400

@app.route('/cookie')
def cookie():
    r = make_response('带 Cookie 的页面')
    r.set_cookie('answer', '42')
    return r

@app.route('/go')
def go():
    return redirect('/')
Javalin
config.routes.get("/", ctx ->
    ctx.status(400).html("<h1>Bad Request</h1>"));

config.routes.get("/cookie", ctx -> {
    ctx.cookie("answer", "42");
    ctx.result("带 Cookie 的页面");
});

config.routes.get("/go", ctx -> ctx.redirect("/"));

标准 HTTP 异常：比 abort() 更好用

Flask 用 abort(404) 中断请求。Javalin 的做法是抛出一个异常， 它自带一组现成的类型，而且会根据客户端的 Accept 头自动决定返回 HTML 还是 JSON： 

import io.javalin.http.*;

config.routes.get("/user/{name}", ctx -> {
    User user = users.findByUsername(ctx.pathParam("name"));
    if (user == null) {
        throw new NotFoundResponse("没有这个用户");
    }
    ctx.html("<h1>Hello, " + user.getUsername() + "</h1>");
});

浏览器（Accept: text/html）收到的是纯文本 没有这个用户；而 API 客户端（Accept: application/json）收到的是：

HTTP/1.1 404 Not Found
Content-Type: application/json

{
  "title": "没有这个用户",
  "status": 404,
  "type": "https://javalin.io/documentation#notfoundresponse",
  "details": []
}

常用的几个（都在 io.javalin.http 包里）：

异常类状态码什么时候用
BadRequestResponse400客户端数据有问题
UnauthorizedResponse401没登录 / 凭证无效
ForbiddenResponse403登录了但权限不够（第 9 章）
NotFoundResponse404资源不存在
ConflictResponse409比如用户名已被占用
InternalServerErrorResponse500服务端自己的问题
ⓘ 异常不是“错误”，是一种控制流

有些人觉得“用异常返回 404 很奇怪”。但注意 abort() 在 Flask 里也是靠抛异常实现的 （原书明确提到了这一点：“abort() 不会把控制权交回函数，因为它抛出了一个异常”）。 用异常的好处是：你在一个嵌套很深的方法里也能立刻终止请求，不用一层层 return 错误码。

Javalin 的“扩展”

原书这一章最后一节讲 Flask 扩展。Javalin 的对应概念有两层：

📦

卫星模块

独立的 Maven 依赖，版本号和 Javalin 核心一致。例如 javalin-rendering-jte（第 3 章）、javalin-micrometer（第 16 章）。

🔧

自带插件

核心里就有，一行 config.bundledPlugins.enableXxx() 打开。CORS、开发日志、路由总览、HTTPS 重定向、全局响应头。

✏

自己写的插件

实现 Plugin 接口，用 config.registerPlugin(...) 注册。本教程大部分“扩展”其实就是普通的 Java 类，不需要插件机制。

☕

任何 Java 库

这才是重点：Javalin 不要求库“适配 Javalin”。Hibernate、Jackson、bcrypt 都是普通 Java 库，直接用。

这一点比 Flask 还宽松：Flask 很多功能要用专门的 Flask-XXX 适配包 （Flask-SQLAlchemy、Flask-Mail、Flask-Login），而 Javalin 几乎不需要这一层 —— 因为没有“应用上下文”要适配。

本章完整代码

package com.example.javalinky;

import io.javalin.Javalin;
import io.javalin.http.NotFoundResponse;

public class App {

    public static void main(String[] args) {
        int port = Integer.parseInt(System.getenv().getOrDefault("PORT", "7070"));

        Javalin.create(config -> {
            // --- 开发期辅助（第 7 章会按环境开关） ---
            config.bundledPlugins.enableDevLogging();
            config.bundledPlugins.enableRouteOverview("/routes");

            // --- 钩子 ---
            config.routes.before(ctx ->
                ctx.attribute("startedAt", System.nanoTime()));

            config.routes.after(ctx -> {
                long started = ctx.attribute("startedAt");
                long ms = (System.nanoTime() - started) / 1_000_000;
                ctx.header("X-Response-Time", ms + "ms");
            });

            // --- 路由 ---
            config.routes.get("/", ctx -> ctx.html("<h1>Hello World!</h1>"));

            config.routes.get("/user/{name}", ctx -> {
                String name = ctx.pathParam("name");
                if (name.isBlank()) throw new NotFoundResponse();
                ctx.html("<h1>Hello, " + name + "!</h1>");
            });

            config.routes.get("/whoami", ctx ->
                ctx.html("<p>你的浏览器是 " + ctx.header("User-Agent") + "</p>"));

        }).start(port);
    }
}
⚠ 一个安全隐患，第 3 章就会修掉

上面的 "<h1>Hello, " + name + "!</h1>" 把用户输入直接拼进 HTML。 如果有人访问 /user/<script>alert(1)</script>，脚本会在访客浏览器里执行 —— 这就是 XSS（跨站脚本）漏洞。

原书同样在这里埋了这个坑，并在第 3 章用模板引擎的自动转义解决。 我们下一章用 JTE 也会解决它，而且 JTE 的转义是编译期按 HTML 上下文决定的，比运行时转义更可靠。

动手练习

  1. 启动应用，访问 http://localhost:7070/routes，看看 Javalin 自己也注册了哪些路由。
  2. 加一个 config.routes.post("/echo", ctx -> ctx.result(ctx.body()))， 然后用 curl -X POST localhost:7070/echo -d 'hello' 测试。 再试试 curl localhost:7070/echo（GET），观察返回 404 还是 405， 然后加上 config.http.prefer405over404 = true 再试一次。
  3. 在 before 里打印 ctx.path()，然后访问一个不存在的 URL。 确认 before 跑了而 beforeMatched 没跑（给 beforeMatched 也加个打印来验证）。
  4. 写一条路由 /boom，在里面 throw new IllegalStateException("炸了")。 观察默认响应和控制台日志。然后加上 config.routes.exception(IllegalStateException.class, (e, ctx) -> ctx.status(500).result("出错了：" + e.getMessage()))， 再看变化。
  5. 用 ctx.pathParamAsClass("id", Integer.class).get() 写一条 /post/{id}， 然后访问 /post/abc，看看 Javalin 自动返回的 400 响应长什么样。
