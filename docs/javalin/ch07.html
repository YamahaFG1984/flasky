大型应用的结构

App.java 已经快两百行了，配置、装配、路由、业务全挤在一个 main 里。 这一章做一次彻底的重构：把配置分层、把应用创建变成一个工厂方法、把路由拆成模块。 重构完之后，第二部分的七章才能顺利地往上加功能。

本章目标

  • 理解“应用工厂”解决什么问题，以及 Javalin 7 为什么天然适合它
  • 用路由模块实现 Flask 蓝本的效果
  • 手工装配依赖，并理解为什么这个项目不需要 Spring

原书给出的 Flask 结构是：应用包 app/ 里按蓝本分子包， 配置在 config.py，入口在 flasky.py，测试在 tests/。 Java 的对应结构是按包分层：

ⓘ 为什么不按“功能”分包

另一种流行的分法是按功能切：user/、post/、comment/， 每个包里都有自己的实体、仓储、路由。这叫“垂直切片”，在大型项目里更好。

本教程用按层分，是因为它和原书的章节推进方式对得上 （第 5 章讲数据层、第 8 章讲 Web 层……），学起来线索更清楚。 真实项目超过几十个类之后，建议改成按功能分。

配置分层

原书用一个配置类继承体系：Config 基类放公共项， DevelopmentConfig / TestingConfig / ProductionConfig 各自覆盖， 最后用一个字典按名字选。

Java 版我们用 record + 静态工厂方法。 比继承更清楚，而且因为 record 是不可变的，配置不会在运行期被偷偷改掉： 

package com.example.javalinky.config;

public enum Profile {
    DEV,     // 本地开发
    TEST,    // 跑单元测试
    PROD;    // 生产

    public static Profile fromEnv(String value) {
        if (value == null || value.isBlank()) return DEV;
        return Profile.valueOf(value.trim().toUpperCase());
    }

    public boolean isDev()  { return this == DEV; }
    public boolean isTest() { return this == TEST; }
    public boolean isProd() { return this == PROD; }
}

先解决“配置从哪来”

原书用 python-dotenv 把 .env 文件读进环境变量。 Java 读不了也写不了自己的环境变量（System.getenv() 是只读的）， 所以我们自己做一个很小的读取器： 

package com.example.javalinky.config;

import java.io.IOException;
import java.nio.file.*;
import java.util.HashMap;
import java.util.Map;

/**
 * 配置来源，优先级从高到低：
 *   1. 真正的环境变量（容器和 PaaS 用这个）
 *   2. 项目根目录的 .env 文件（本地开发用这个）
 *   3. 代码里写的默认值
 */
public final class Env {

    private final Map<String, String> dotenv;

    private Env(Map<String, String> dotenv) {
        this.dotenv = dotenv;
    }

    public static Env load() {
        return new Env(readDotenv(Path.of(".env")));
    }

    public String get(String key, String defaultValue) {
        String fromEnv = System.getenv(key);
        if (fromEnv != null && !fromEnv.isBlank()) return fromEnv;

        String fromFile = dotenv.get(key);
        if (fromFile != null && !fromFile.isBlank()) return fromFile;

        return defaultValue;
    }

    /** 必填项：缺了就直接启动失败，而不是在运行时才报莫名其妙的错 */
    public String require(String key) {
        String value = get(key, null);
        if (value == null) {
            throw new IllegalStateException(
                "缺少必需的配置项 " + key + "（请设置环境变量或写进 .env）");
        }
        return value;
    }

    public int getInt(String key, int defaultValue) {
        return Integer.parseInt(get(key, String.valueOf(defaultValue)));
    }

    public boolean getBoolean(String key, boolean defaultValue) {
        return Boolean.parseBoolean(get(key, String.valueOf(defaultValue)));
    }

    private static Map<String, String> readDotenv(Path path) {
        Map<String, String> map = new HashMap<>();
        if (!Files.exists(path)) return map;
        try {
            for (String line : Files.readAllLines(path)) {
                line = line.trim();
                if (line.isEmpty() || line.startsWith("#")) continue;
                int eq = line.indexOf('=');
                if (eq <= 0) continue;
                String key = line.substring(0, eq).trim();
                String value = line.substring(eq + 1).trim();
                // 去掉可能存在的引号
                if (value.length() >= 2
                        && (value.startsWith("\"") && value.endsWith("\"")
                         || value.startsWith("'") && value.endsWith("'"))) {
                    value = value.substring(1, value.length() - 1);
                }
                map.put(key, value);
            }
        } catch (IOException e) {
            throw new UncheckedIOException("读取 .env 失败", e);
        }
        return map;
    }
}

有现成的库：io.github.cdimascio:dotenv-java。 这里手写是因为 40 行能讲清楚它在干什么，而且省一个依赖。 真实项目里也常用 Typesafe Config（HOCON 格式）或 MicroProfile Config。

AppConfig

package com.example.javalinky.config;

import com.example.javalinky.mail.MailConfig;

public record AppConfig(
    Profile profile,
    int port,
    String siteBaseUrl,

    // 数据库
    String jdbcUrl,
    String dbUser,
    String dbPassword,

    // 安全
    String secretKey,          // 签发令牌用（第 8 章）
    boolean httpsOnly,         // 会话 Cookie 是否只在 HTTPS 下发送

    // 邮件
    MailConfig mail,
    String adminEmail,

    // 分页（原书的 FLASKY_*_PER_PAGE）
    int postsPerPage,
    int followersPerPage,
    int commentsPerPage,

    // 性能（第 16 章）
    long slowQueryMillis,

    // 开发辅助
    boolean devLogging,
    boolean routeOverview,
    boolean templateHotReload
) {

    public static AppConfig load() {
        Env env = Env.load();
        Profile profile = Profile.fromEnv(env.get("APP_PROFILE", "dev"));
        return switch (profile) {
            case DEV  -> dev(env);
            case TEST -> test(env);
            case PROD -> prod(env);
        };
    }

    // ---------- 开发 ----------
    private static AppConfig dev(Env env) {
        return new AppConfig(
            Profile.DEV,
            env.getInt("PORT", 7070),
            env.get("SITE_BASE_URL", "http://localhost:7070"),
            env.get("DATABASE_URL", "jdbc:h2:./data/javalinky-dev;MODE=PostgreSQL"),
            env.get("DATABASE_USER", "sa"),
            env.get("DATABASE_PASSWORD", ""),
            env.get("SECRET_KEY", "dev-only-insecure-key-change-in-prod"),
            false,
            MailConfig.fromEnv(),
            env.get("ADMIN_EMAIL", "admin@example.com"),
            20, 50, 30,
            500,
            true, true, true
        );
    }

    // ---------- 测试 ----------
    private static AppConfig test(Env env) {
        return new AppConfig(
            Profile.TEST,
            0,                       // 0 = 让系统随便分配一个空闲端口
            "http://localhost",
            // 每次测试一个全新的内存库，互不干扰
            "jdbc:h2:mem:test-" + java.util.UUID.randomUUID() + ";MODE=PostgreSQL",
            "sa", "",
            "test-secret-key",
            false,
            MailConfig.disabled(),   // 测试时不真的发邮件
            "admin@example.com",
            20, 50, 30,
            Long.MAX_VALUE,          // 测试里不报慢查询
            false, false, true
        );
    }

    // ---------- 生产 ----------
    private static AppConfig prod(Env env) {
        return new AppConfig(
            Profile.PROD,
            env.getInt("PORT", 8080),
            env.require("SITE_BASE_URL"),      // ← 生产必须显式给
            env.require("DATABASE_URL"),
            env.require("DATABASE_USER"),
            env.require("DATABASE_PASSWORD"),
            env.require("SECRET_KEY"),         // ← 绝不能用默认值
            env.getBoolean("HTTPS_ONLY", true),
            MailConfig.fromEnv(),
            env.require("ADMIN_EMAIL"),
            env.getInt("POSTS_PER_PAGE", 20),
            env.getInt("FOLLOWERS_PER_PAGE", 50),
            env.getInt("COMMENTS_PER_PAGE", 30),
            env.getInt("SLOW_QUERY_MILLIS", 500),
            false, false, false                // 生产环境关掉所有开发辅助
        );
    }
}
☀ 这个设计里有三个值得学的决定
  1. 开发有默认值，生产用 require()。 这样 git clone 之后不配任何东西就能跑起来， 但生产环境少配一个变量会立刻启动失败， 而不是带着 "dev-only-insecure-key" 上线。
  2. 开发辅助开关（devLogging / routeOverview）进了配置。 第 2 章提醒过它们会泄露敏感信息，现在从结构上保证了生产不会开。
  3. switch 用了 Java 的穷尽检查。 给 Profile 加一个新枚举值（比如 STAGING）， 这个 switch 会编译失败，提醒你补上对应配置。

应用工厂

原书说得很准确：问题在于“应用实例在全局作用域创建，等脚本跑起来的时候已经太晚了， 没法再改配置”。而单元测试偏偏需要用不同配置创建多个实例。 Flask 的解法是把创建过程挪进 create_app(config_name) 工厂函数。

☀ Javalin 7 让这件事变得毫无摩擦

回想第 2 章那条警告：Javalin 7 要求路由必须在 create() 的配置块里注册。

这个限制本身就强制你写成工厂模式 —— 不可能像 Flask 单文件版那样“在全局作用域上挂路由”。 换句话说，Flask 要讲一整节才能说服你改用工厂函数的事，Javalin 7 直接在 API 层面规定了。

实现

package com.example.javalinky;

import com.example.javalinky.config.AppConfig;
import com.example.javalinky.db.Db;
import com.example.javalinky.db.UnitOfWork;
import com.example.javalinky.mail.MailService;
import com.example.javalinky.mail.Mailer;
import com.example.javalinky.web.*;
import com.example.javalinky.web.routes.*;
import gg.jte.TemplateEngine;
import io.javalin.Javalin;
import io.javalin.http.staticfiles.Location;
import io.javalin.rendering.template.JavalinJte;

/** 应用工厂：给一份配置，返回一个配好但还没启动的 Javalin 实例。 */
public final class JavalinkyApp {

    public static Javalin create(AppConfig cfg) {

        // ---------- 1. 基础设施 ----------
        Db.init(cfg.jdbcUrl(), cfg.dbUser(), cfg.dbPassword());

        Mailer mailer = new Mailer(cfg.mail());
        MailService mail = new MailService(mailer, cfg.siteBaseUrl());

        TemplateEngine templates = cfg.templateHotReload()
            ? Templates.directory()      // 开发：从 src/main/jte 读，改了就生效
            : Templates.precompiled();   // 生产：读 jar 里预编译好的模板类

        // ---------- 2. 业务装配 ----------
        Services services = Services.wire(cfg, mail);

        // ---------- 3. Web ----------
        return Javalin.create(javalin -> {

            javalin.fileRenderer(new JavalinJte(templates));

            javalin.staticFiles.add(f -> {
                f.directory = "/public";
                f.location = Location.CLASSPATH;
                f.hostedPath = "/";
            });

            javalin.jetty.modifyServletContextHandler(h ->
                h.setSessionHandler(Sessions.handler(cfg.httpsOnly())));

            javalin.concurrency.useVirtualThreads = true;

            // 过滤器（顺序有讲究，见下面的说明）
            UnitOfWork.install(javalin);
            Csrf.install(javalin);

            // 按配置开关开发辅助
            if (cfg.devLogging())    javalin.bundledPlugins.enableDevLogging();
            if (cfg.routeOverview()) javalin.bundledPlugins.enableRouteOverview("/routes");
            if (cfg.httpsOnly())     javalin.bundledPlugins.enableSslRedirects();

            // 错误页
            ErrorPages.install(javalin);

            // 路由模块（相当于 Flask 的蓝本）
            new MainRoutes(cfg, services).register(javalin);
            new AuthRoutes(cfg, services).register(javalin);
            new ApiRoutes(cfg, services).register(javalin);

            // 优雅关闭
            javalin.events.serverStopping(() -> {
                mailer.close();
                Db.close();
            });
        });
    }

    private JavalinkyApp() {}
}
⚠ 过滤器的注册顺序很重要

Javalin 按注册顺序执行同类型的过滤器。我们的顺序是：

  1. UnitOfWork 的 before：开事务（最先，这样后面所有东西都能用数据库）
  2. Csrf 的 before：校验令牌（可能抛 403）
  3. …… 第 8 章会在这里插入“加载当前用户”

after 过滤器的执行顺序也是注册顺序，所以 UnitOfWork 的提交会在最前面 —— 这正是我们要的： 其他 after 过滤器（比如记录响应时间）看到的是已提交的状态。

路由模块：蓝本的 Java 版

Flask 蓝本解决两个问题：把路由按功能分文件，以及给路由加 URL 前缀 （url_prefix='/auth'）。 Javalin 的组合拳是：一个你自己定义的接口 + apiBuilder 的 path() 分组。 

package com.example.javalinky.web.routes;

import io.javalin.config.JavalinConfig;

/** 一组相关的路由。相当于 Flask 的一个蓝本。 */
public interface RouteModule {
    void register(JavalinConfig config);
}

package com.example.javalinky.web.routes;

import com.example.javalinky.config.AppConfig;
import com.example.javalinky.web.*;
import io.javalin.config.JavalinConfig;

import static io.javalin.apibuilder.ApiBuilder.*;

public class AuthRoutes implements RouteModule {

    private final AppConfig cfg;
    private final Services services;

    public AuthRoutes(AppConfig cfg, Services services) {
        this.cfg = cfg;
        this.services = services;
    }

    @Override
    public void register(JavalinConfig config) {
        config.routes.apiBuilder(() -> {
            // 这个 path 块里的所有路由都自动带上 /auth 前缀
            path("/auth", () -> {
                get("/login", this::loginForm);
                post("/login", this::login);
                get("/logout", this::logout);
                get("/register", this::registerForm);
                post("/register", this::register);
                get("/confirm/{token}", this::confirm);
                // 第 8 章会填满这里
            });
        });
    }

    private void loginForm(Context ctx) {
        View.render(ctx, "auth/login.jte", "登录", "form", FormView.empty());
    }

    private void login(Context ctx) {
        // 第 8 章实现
    }

    // ... 其余处理器
}
💡 this::loginForm 是什么写法

这是 Java 的方法引用，等价于 ctx -> this.loginForm(ctx)。 用它的好处：每个处理器是一个有名字的方法，调用栈里能看到 AuthRoutes.loginForm，而不是一堆 lambda$register$3。 这让日志和异常堆栈可读得多。

方法签名必须匹配 Handler 接口：接收 Context，返回 void， 可以 throws Exception。

依赖装配：为什么不用 Spring

AuthRoutes 需要 Services，Services 需要仓储和邮件服务， 仓储需要 EntityManager…… 这些对象谁来创建、怎么传给需要的人？ 这就是“依赖注入”要解决的问题。

Spring 的答案是：加 @Autowired，由容器在运行时扫描、反射、注入。 本教程的答案是：用构造器传，在一个地方全部手工 new 出来。 

package com.example.javalinky.web;

import com.example.javalinky.config.AppConfig;
import com.example.javalinky.db.Db;
import com.example.javalinky.db.*;
import com.example.javalinky.mail.MailService;
import com.example.javalinky.service.*;
import io.javalin.http.Context;

/**
 * 整个应用的依赖装配表。
 * 注意：Repository 依赖"当前请求的 EntityManager"，所以不能提前创建好，
 * 要在处理器里按需造 —— 这就是下面那些工厂方法。
 */
public record Services(
    AppConfig config,
    MailService mail,
    AuthService auth,
    PostService posts
) {

    public static Services wire(AppConfig cfg, MailService mail) {
        var auth = new AuthService(cfg, mail);
        var posts = new PostService(cfg);
        return new Services(cfg, mail, auth, posts);
    }

    // ---- 请求级别的仓储（每次调用都用当前请求的 EntityManager）----
    public UserRepository users(Context ctx)    { return new UserRepository(Db.em(ctx)); }
    public RoleRepository roles(Context ctx)    { return new RoleRepository(Db.em(ctx)); }
    public PostRepository postRepo(Context ctx) { return new PostRepository(Db.em(ctx)); }
}
ⓘ 这不是反对 Spring

Spring Boot 在大型团队项目里有巨大价值：事务注解、安全框架、监控端点、 成千上万个现成的 starter。

但对于学习来说，它有个副作用：很多 Web 开发的基本机制被自动配置藏起来了， 你写了三年 Spring 可能还不知道会话存在哪、拦截器什么时候跑、事务边界在哪划。 本教程先把这些东西亲手做一遍，之后你用 Spring 会用得更明白。

💡 scope 是 Java 比 Python 多出来的一个概念
scope含义Python 的对应
compile（默认）编译和运行都需要，会打进最终产物requirements.txt
test只在测试时需要，不会打进生产 jarrequirements/dev.txt
runtime编译时不需要（比如 JDBC 驱动）—
provided运行环境会提供（传统 Servlet 容器部署时用）—

原书用 requirements/ 目录放 common.txt、dev.txt、prod.txt 来区分环境依赖。Maven 用 scope 做同一件事，而且更精确。

和 pip freeze 对应的东西

Maven 没有 lock 文件，但依赖解析是确定性的（同样的 pom 在任何机器上解析出同样的版本）， 所以不需要 lock。想看完整的实际依赖： 

mvn dependency:tree                   # 完整依赖树
mvn dependency:tree -Dverbose         # 带上被版本仲裁掉的分支
mvn dependency:list                   # 平铺列表，接近 pip freeze
mvn versions:display-dependency-updates   # 哪些能升级

第一批单元测试

原书这一节写了两个很简单的测试：确认应用实例存在、确认它跑在测试配置下。 我们也从这里开始 —— 第 15 章才会系统地讲测试。 

package com.example.javalinky;

import com.example.javalinky.config.AppConfig;
import com.example.javalinky.config.Profile;
import io.javalin.Javalin;
import io.javalin.testtools.JavalinTest;
import org.junit.jupiter.api.Test;

import static org.assertj.core.api.Assertions.assertThat;

class BasicsTest {

    @Test
    void 测试配置使用内存数据库() {
        AppConfig cfg = testConfig();
        assertThat(cfg.profile()).isEqualTo(Profile.TEST);
        assertThat(cfg.jdbcUrl()).startsWith("jdbc:h2:mem:");
        assertThat(cfg.devLogging()).isFalse();
    }

    @Test
    void 首页返回200() {
        Javalin app = JavalinkyApp.create(testConfig());

        // JavalinTest 会在一个随机端口上真的启动服务器，
        // 给你一个 HTTP 客户端，测完自动关掉
        JavalinTest.test(app, (server, client) -> {
            var response = client.get("/");
            assertThat(response.code()).isEqualTo(200);
            assertThat(response.body().string()).contains("Javalinky");
        });
    }

    @Test
    void 不存在的页面返回404() {
        JavalinTest.test(JavalinkyApp.create(testConfig()), (server, client) -> {
            assertThat(client.get("/这个页面不存在").code()).isEqualTo(404);
        });
    }

    private static AppConfig testConfig() {
        // 让 AppConfig.load() 走 TEST 分支。
        // 第 15 章会用一个更干净的办法（直接暴露一个 AppConfig.forTest() 工厂）
        return AppConfig.load();
    }
}

ⓘ 方法名可以用中文？

可以 —— Java 的标识符支持 Unicode。JUnit 5 的测试方法名用中文（或 @DisplayName 注解） 能让测试报告直接读成一句话。生产代码里不建议这么干，但测试方法名是个例外，很多团队在用。

打包：一个 JAR 就是全部

原书第 17 章才讲部署。但 Java 这边有个很愉快的事实值得提前说： Javalin 应用可以打成一个自带服务器的 JAR， 不需要 Gunicorn、不需要 Tomcat、不需要在目标机器上装任何依赖（除了 JRE）。 

<plugin>
  <groupId>org.apache.maven.plugins</groupId>
  <artifactId>maven-shade-plugin</artifactId>
  <version>3.6.0</version>
  <executions>
    <execution>
      <phase>package</phase>
      <goals><goal>shade</goal></goals>
      <configuration>
        <createDependencyReducedPom>false</createDependencyReducedPom>
        <finalName>javalinky</finalName>
        <transformers>
          <!-- 写入 Main-Class，这样 java -jar 才知道从哪开始 -->
          <transformer implementation=
            "org.apache.maven.plugins.shade.resource.ManifestResourceTransformer">
            <mainClass>com.example.javalinky.App</mainClass>
          </transformer>
          <!-- 合并多个 jar 里同名的 service 描述文件，少了它 Hibernate 会启动失败 -->
          <transformer implementation=
            "org.apache.maven.plugins.shade.resource.ServicesResourceTransformer"/>
        </transformers>
      </configuration>
    </execution>
  </executions>
</plugin>

mvn clean package
ls -lh target/javalinky.jar          # 大约 40 MB，包含所有依赖

java -jar target/javalinky.jar       # 直接就能跑
⚠ 打包后模板加载方式必须切换

JAR 里没有 src/main/jte 目录，所以 Templates.directory() 在生产环境会找不到模板。 这就是 AppConfig.templateHotReload 这个开关存在的原因。

生产模式要用预编译的模板，需要加 JTE 的 Maven 插件。 完整配置在第 17 章，这里先知道有这回事： 

<plugin>
  <groupId>gg.jte</groupId>
  <artifactId>jte-maven-plugin</artifactId>
  <version>${jte.version}</version>
  <configuration>
    <sourceDirectory>${basedir}/src/main/jte</sourceDirectory>
    <contentType>Html</contentType>
  </configuration>
  <executions>
    <execution>
      <phase>generate-sources</phase>
      <goals><goal>generate</goal></goals>
    </execution>
  </executions>
</plugin>

Cli：维护命令

原书用 @app.cli.command() 加了 test、profile、deploy 几个命令。 Javalin 没有 CLI 框架，但我们不需要 —— 一个 main 加一个 switch 就够： 

package com.example.javalinky;

import com.example.javalinky.config.AppConfig;
import com.example.javalinky.db.Db;
import com.example.javalinky.service.SeedService;

public class Cli {

    public static void main(String[] args) {
        if (args.length == 0) {
            usage();
            System.exit(1);
        }

        AppConfig cfg = AppConfig.load();

        switch (args[0]) {
            case "migrate" -> {
                // Db.init 内部就会跑 Flyway
                Db.init(cfg.jdbcUrl(), cfg.dbUser(), cfg.dbPassword());
                System.out.println("数据库已升级到最新版本");
            }
            case "seed-roles" -> run(cfg, () -> SeedService.insertRoles());
            case "fake" -> {
                int users = args.length > 1 ? Integer.parseInt(args[1]) : 50;
                int posts = args.length > 2 ? Integer.parseInt(args[2]) : 200;
                run(cfg, () -> SeedService.fake(users, posts));
            }
            // 第 17 章：部署时执行的一组任务
            case "deploy" -> run(cfg, () -> {
                SeedService.insertRoles();
                SeedService.addSelfFollows();
            });
            default -> {
                System.err.println("未知命令：" + args[0]);
                usage();
                System.exit(1);
            }
        }
        Db.close();
    }

    private static void run(AppConfig cfg, Runnable task) {
        Db.init(cfg.jdbcUrl(), cfg.dbUser(), cfg.dbPassword());
        var em = Db.emf().createEntityManager();
        try {
            em.getTransaction().begin();
            SeedService.use(em);
            task.run();
            em.getTransaction().commit();
            System.out.println("完成");
        } catch (RuntimeException e) {
            if (em.getTransaction().isActive()) em.getTransaction().rollback();
            throw e;
        } finally {
            em.close();
        }
    }

    private static void usage() {
        System.err.println("""
            用法：java -cp javalinky.jar com.example.javalinky.Cli <命令>

              migrate            跑数据库迁移
              seed-roles         创建/更新角色（可重复执行）
              fake [用户数] [文章数]  生成假数据（开发用）
              deploy             部署时执行的全部任务
            """);
    }
}

# 开发时
mvn -q compile exec:java -Dexec.mainClass=com.example.javalinky.Cli -Dexec.args="seed-roles"

# 打包之后
java -cp target/javalinky.jar com.example.javalinky.Cli deploy
💡 为什么是 -cp 而不是 -jar

java -jar 只会执行 manifest 里写的那个 Main-Class（App）。 要跑别的 main 方法就用 -cp 指定 classpath + 全限定类名。 一个 JAR 里可以有任意多个入口。

动手练习

  1. 按本章的结构把前六章的代码重新组织一遍。这个过程会很啰嗦，但必须亲手做 —— 后面所有章节都假设你的项目是这个结构。
  2. 故意不设 SECRET_KEY，用 APP_PROFILE=prod mvn -q compile exec:java 启动。 确认它启动失败并告诉你缺哪个变量。这就是 require() 的价值。
  3. 给 Profile 加一个 STAGING 枚举值，然后 mvn compile。 看 AppConfig.load() 里的 switch 怎么报错。补上分支让它通过。
  4. 写一个 MainRoutes，把第 3–6 章的首页和用户页路由搬进去，用 apiBuilder 注册。 启动后访问 /routes 确认路由都在。
  5. 执行 mvn clean package，然后 java -jar target/javalinky.jar。 它会因为找不到模板而失败 —— 读一下错误信息，理解为什么。 （先别急着修，第 17 章会完整解决。）
  6. 在 .gitignore 里确认 .env 和 jte-classes/ 都被忽略了， 然后 git status 确认没有意外的文件要提交。
