报错速查

拿着报错信息来这里搜（Ctrl+F）。 按「什么时候炸的」分组：编译期最好查，运行期最难查， 而最坑的那一类是「不报错但行为不对」 —— 单独列在最后一节。

ⓘ 关于这些报错文本的来源

标 ✓ 的，是写这本书的配套代码时真的撞上并记录下来的原文 （完整清单在 javalinky/TUTORIAL-DIFFS.md）。 没标的是 Java / Maven / Hibernate 生态里的常见报错， 具体文字可能因版本略有出入，但关键词和原因是对的。

编译期：mvn compile 过不去

报错里的关键词原因怎么办
✓ cannot find symbol: method
directoryTemplateEngine()		 Javalin 是 Kotlin 写的，这是 companion object 里的方法 Java 侧要写 JavalinJte.Companion.directoryTemplateEngine()（第 3 章）
cannot find symbol: method allowNullable() Javalin 6 删掉了这个方法 改用 getOrNull()（第 4 章）
✓ method post in class MainRoutes
cannot be applied to given types
required: Context / found: String, Handler		 你定义的实例方法 post(Context) 遮蔽了静态导入的 ApiBuilder.post。报错指向的是注册路由那一行，真正的原因在几十行外 处理器改名 showPost。get/put/delete/path 同理（第 11 章）
incompatible types: Object cannot be
converted to X		 ctx.attribute("k") 这类泛型方法推不出类型 显式声明：User u = ctx.attribute("k");
variable x might not have been initialized
local variables referenced from a lambda
must be final or effectively final		 lambda 不能改外部局部变量 用单元素数组或 AtomicReference。但要先确认那个回调 只会执行一次 —— 第 19 章讲了 compute 可以、 updateAndGet 不可以
release version 21 not supported
invalid target release: 21		 JDK 版本比 maven.compiler.release 低 mvn -version 看 Maven 实际用的是哪个 JDK；用 JAVA_HOME 指到 21+
in comment after two dashes (--)
is not allowed		 pom.xml 的 XML 注释里出现了连续的 -- （比如拿它画分隔线） XML 注释里不能有 --，换成别的符号

模板也是编译的（这是 JTE 的卖点），所以它的错误也出现在 mvn compile 阶段， 而且会指出 .jte 文件的行号。

报错原因怎么办
✓ Illegal HTML attribute name
@if(required)required@endif!
Expressions in HTML attribute names are not
allowed. Smart attributes will do just that		 @if 放在了属性名的位置 用智能属性：required="${required}"。值为 null/false 时整个属性不输出（第 4 章）
Failed to compile template ...
cannot find symbol		 模板里调了实体上不存在的方法，或者 @import 漏了 按行号去看。这正是 JTE 的价值 —— Jinja2 要等到访问那个页面才发现
Unexpected @endif / Unexpected end of
template		 @if / @for 没配对 检查嵌套。注意 @elseif 不是 @else if

启动期：编译过了，一跑就挂

报错里的关键词原因怎么办
✓ NoClassDefFoundError: gg/jte/Content 用了 mvn exec:java。它在 Maven 自己的 JVM 里跑， 而 JTE 运行时编译模板用的类加载器父级是系统类加载器， 那里没有你的依赖 改用 mvn exec:exec（fork 一个真正的 JVM）。 第 3 章有完整解释和 pom 配置
✓ Database may be already in use:
".../data/javalinky-dev.mv.db".
Possible solutions: close all other
connection(s) [90020-232]		 H2 的文件库同一时刻只能被一个进程打开。 你多半是：已经有一个应用在跑、或者 JShell 还连着、 或者上一次没退干净 关掉另一个进程。要同时连多个，用 H2 的 server 模式 （jdbc:h2:tcp://localhost/~/db）
✓ SecurityException: Invalid signature
file digest for Manifest main attributes		 fat jar 里混进了依赖自带的签名文件（本项目是 bcrypt 的 META-INF/PFOPENSO.SF），shade 重新打包后摘要对不上 maven-shade-plugin 加 <filters> 排除 META-INF/*.SF、*.DSA、*.RSA（第 7 章）
BindException: Address already in use 端口被占了 lsof -i :7070 找出来；或者换个端口 PORT=7071
Schema-validation: missing table [posts]
Schema-validation: missing column [about_me]		 hbm2ddl.auto=validate 发现实体和表对不上 —— 你改了实体但没写迁移 写一个新的 V8__xxx.sql。 这个报错是在帮你，别去改成 update（第 5 章）
Validate failed: Migration checksum
mismatch for migration version 3		 改了一个已经执行过的迁移文件 迁移是只增不改的。开发库可以删库重来， 生产环境只能写一个新迁移去修正
UnsupportedClassVersionError:
... has been compiled by a more recent version		 编译用的 JDK 比运行用的新 对齐两边版本。常见于本地 21 编译、服务器 17 运行
启动后终端被几百行 DEBUG 刷屏 没有 logback.xml，Logback 退回默认的 DEBUG 级别 加一个最小的 src/main/resources/logback.xml（第 2 章）

运行期：某个页面或操作炸了

报错里的关键词原因怎么办
✓ No parameter with name baseUrl is
defined in tag/pagination.jte		 模板里用了 Razor 风格的注释 @* … *@，JTE 不认， 于是整行被当成了参数名的一部分。参数明明就写在那里 JTE 的注释是 <%-- --%>（第 11 章）
✓ NoSuchMethodError: 'void com.fasterxml
.jackson.core.util.BufferRecycler
.releaseToPool()'		 依赖版本冲突：jackson-databind 是新的， 传递进来的 jackson-core 是旧的 mvn dependency:tree -Dincludes=com.fasterxml.jackson 确认， 然后 import jackson-bom（第 8 章）
NoSuchMethodError / NoSuchFieldError
（任何一个）		 几乎总是同一个病：类找到了，但版本不对。 注意它和 ClassNotFoundException 的区别 —— 后者是压根没有 同上。这条值得单独记住，它是 Java 依赖地狱的标准症状
LazyInitializationException: could not
initialize proxy - no Session		 事务已经结束（UnitOfWork 的 after 跑完了）， 才去访问懒加载的关联。常见于在模板里点出一个没取过的关联 查询时 join fetch 把它取出来， 或者在事务内把要用的数据装进页面模型 record（第 11 章的做法）
IllegalStateException: 没有默认角色 测试或新库里没灌角色，defaultRole() 查不到。 表现是注册返回 500，而错误信息完全看不出和角色有关 先跑 exec:exec@cli -Dcli.args="seed-roles"； 测试里用 TestFixtures.seedRoles(em)（第 9 章）
Cannot invoke "X.y()" because "<local1>"
is null		 NPE。Java 14+ 的报错会明确指出是哪个表达式， 比老版本的「NullPointerException」一行好查太多 认真读那个变量名。常见来源：ctx.formParam() 对不存在的字段返回 null
所有请求突然一起卡住，CPU 却不高 虚拟线程被 pinning 钉住了载体线程 （JDK 21 下在 synchronized 块里做阻塞 I/O）； 或者连接池耗尽 -Djdk.tracePinnedThreads=full 启动看栈； synchronized 换 ReentrantLock（第 19 章）
OutOfMemoryError: Java heap space
（批量导入时）		 EntityManager 的一级缓存持有它管过的所有实体， 而且每次 flush 都要遍历全部对象做脏检查 每 N 条 em.flush() + em.clear()。 注意 clear 之后之前拿到的实体变成游离态，要重新取（第 11 章）

测试阶段

症状原因怎么办
✓ Table "USERS" not found
(this database is empty)		 H2 内存库在最后一个连接关闭时整个消失。 Flyway 建完表把连接还回池里，库就没了。 "this database is empty" 这半句是关键线索 —— 不是迁移没跑，是跑完又被丢了 JDBC URL 加 ;DB_CLOSE_DELAY=-1（第 7、15 章）
✓ 表单 POST 的字段全是 null， 处理器一直回「请填写 xxx」，但请求确实发出去了 client.post(path, Map) 发的是 JSON， 而 ctx.formParam() 只认 application/x-www-form-urlencoded 用 FormBody.Builder + client.request(path, req -> req.post(body))（第 8、15 章）
✓ AssertionError: 页面里应该有 _csrf 隐藏域 （在一个测试里换账号时） GET /auth/login 在已登录时会重定向到首页， 于是取令牌的那次请求拿到的是 302 的空响应体 换账号要先登出：switchUser() = logout + login（第 15 章）
cannot find symbol: method header(String) （在 Response 上） javalin-testtools 7.x 底层换成了 java.net.http，不再是 OkHttp response.headers().get("Location").get(0)（第 15 章）
测试改了你的开发数据，而且时好时坏 忘了 APP_PROFILE=test，测试跑在 DEV 档位， 连的是真实的开发库 把它配进 surefire 的 <environmentVariables>， 别依赖人记得（第 15 章）
并发测试一次都没红过， 但你知道那段代码有竞态 很可能用了虚拟线程。它们挤在 CPU 核数个载体线程上， 纳秒级的临界区根本碰不到一起 测竞态要用平台线程，数量远超核数，再跑几轮。 第 19 章有实测数据：2 核机器上 200 虚拟线程发现率 0%， 500 平台线程 84%

最危险的一类：不报错，但行为不对

上面所有报错至少还会告诉你出事了。 下面这些不会 —— 它们安静地做错事，你只能靠主动检查发现。

症状真正的原因章
✓ 慢请求日志里 requestId 是空的：WARN [] 慢请求 GET / RequestId 装在了 Timing 前面。 Javalin 的 after 过滤器按注册顺序执行，不是倒序， 所以清理 MDC 的那个先跑了 17
✓ Server-Timing 里的 db;dur 恒等于 0 只注册了 statement_inspector。它只在 SQL 发出之前 被调用一次，没法知道执行了多久 —— 耗时要靠 SessionEventListener 16
✓ 生产环境的滚动日志文件和错误邮件从来没生效过 Logback 默认只找 logback.xml。 做了一份 logback-prod.xml 但启动命令没加 -Dlogback.configurationFile= 17
✓ fake 30 60 只造出 3 个用户 中文 locale 的 Faker 给出 峻熙.梁丘 这样的用户名和 .@hotmail.com 这样的邮箱，几条之后全部撞车 11
慢查询日志一条都没有，但页面确实很慢 写的是 hibernate.session.events.log.LOG_QUERIES_SLOWER_THAN_MS。 Hibernate 7 已经没有这个属性了，留着不报错，只是不生效 16
限流把所有用户一起挡了，第 6 个人就进不来 跑在反向代理后面，ctx.ip() 拿到的是代理的地址， 所有人共用一个桶 19
限流配额莫名其妙翻倍了 部署了两个实例。JVM 内的锁和原子操作只在一个进程内有效 19
首页越来越慢，但每条 SQL 都很快 N+1。单条都快，架不住发了 21 条 11、16
复选框永远是选中的 写成了 checked="false"。 HTML 的布尔属性只看在不在，不看值 —— checked="false" 等于选中 4
用户列表里「关注时间」一片空白 页面模型里那个字段填成了 null。 渲染不报错，只是什么都不显示 12
☀ 从这张表里能总结出三条经验
  1. 「配了但不生效」比「配错了报错」危险得多。 上面有三条属于这一类（Hibernate 属性改名、logback 没指定、systemd 键放错段）。 凡是加了配置，都该验证它真的起作用了 —— 看日志里有没有、用 systemd-analyze verify、 或者故意触发一次看看。
  2. 读报错要读完整句。Table "USERS" not found 会让你去查迁移，而真正的线索在后半句 (this database is empty)。 Illegal HTML attribute name 的最后一句 Smart attributes will do just that 直接就是答案。
  3. NoSuchMethodError 永远先想依赖冲突。 它和 ClassNotFoundException 的区别是整个 Java 依赖体系里 最值得记住的一条：前者是版本不对，后者是压根没有。
