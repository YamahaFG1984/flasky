    config.routes.put   ("/post/{id}",   ctx -> {});

    config.routes.apiBuilder(() -> {
        path("/auth", () -> {                      // 块内自动带 /auth 前缀
            get ("/login", this::loginForm);
            post("/login", this::login);
        });

        // path 上挂角色 → 块内所有路由继承
        path("/moderate", List.of(Permission.MODERATE), () -> {
            get("", this::moderate);
        });

        ws ("/live",  wsConfig -> {});             // WebSocket
        sse("/events", client   -> {});            // Server-Sent Events
    });

    // ---- 过滤器（按注册顺序执行，after 也是正序）----
    config.routes.before       (ctx -> {});        // 每个请求，含静态文件
    config.routes.beforeMatched(ctx -> {});        // 只在匹配到路由时
    config.routes.after        (ctx -> {});
    config.routes.afterMatched (ctx -> {});

    // ---- 错误与异常 ----
    config.routes.error(404, "html", ctx -> {});   // 按 Accept 分流
    config.routes.error(404, "json", ctx -> {});
    config.routes.exception(MyException.class, (e, ctx) -> {});

⚠ 路径参数：花括号和尖括号不一样

{name} 不跨 /，<name> 跨 /。 /files/{path} 匹配不到 /files/a/b.txt， 要写 /files/<path>。

ⓘ 抛异常比手写状态码更省事
throw new BadRequestResponse("参数不对");       // 400
throw new UnauthorizedResponse();              // 401
throw new ForbiddenResponse("没有权限");        // 403
throw new NotFoundResponse("文章不存在");        // 404
throw new ConflictResponse();                  // 409

它们都是 HttpResponseException 的子类，会被 Javalin 接住并 按 Accept 头渲染成 HTML 错误页或 JSON 错误体。 在一长串 orElseThrow 里尤其好用。

  ${post.title()}
@endfor

@endfor

<%-- 智能属性：值是 null / false 时整个属性消失 --%>
<input required="${required}" autocomplete="${autocomplete}">

<%-- 调用别的模板（tag/field.jte）--%>
@template.tag.field(form = form, name = "email", label = "邮箱", required = true)

<%-- 布局：被调用方声明 @param gg.jte.Content content --%>
@template.layout.base(layout = layout, content = @`
  <h1>正文写在这里</h1>
`)
⚠ 三个最容易写错的地方
  1. 注释是 <%-- --%>，不是 @* *@（第 11 章）
  2. 属性名的位置不能写 @if，要用智能属性（第 4 章）
  3. 布局内容块用的是反引号 @`…`，不是引号

JPA / JPQL

// ---- 实体 ----
@Entity @Table(name = "users")
public class User {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 64, unique = true)
    private String email;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "role_id")
    private Role role;

    @OneToMany(mappedBy = "author", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Post> posts = new ArrayList<>();

    @PrePersist  void onCreate() {}      // 插入前
    @PreUpdate   void onUpdate() {}      // 更新前
}

// ---- 增删改查 ----
em.persist(user);                        // 新增（INSERT 可能延迟到提交）
em.find(User.class, 1L);                 // 按主键，走一级缓存
em.getReference(User.class, 1L);         // 只要代理，不查库（赋外键时用它）
em.remove(user);
em.flush();                              // 强制把挂起的 SQL 发出去
em.clear();                              // 清空一级缓存（批量插入时配合 flush）

// 改字段就够了 —— 托管实体会被脏检查，不需要 save()
user.setName("新名字");

// ---- 查询 ----
em.createQuery("select u from User u where u.email = :e", User.class)
  .setParameter("e", email)
  .getResultStream().findFirst();        // 比 getSingleResult() 好：没有不抛异常

em.createQuery("""
        select p from Post p
          join fetch p.author             -- ← 避免 N+1 的关键
         where p.author in :authors
         order by p.timestamp desc
        """, Post.class)
  .setParameter("authors", authors)
  .setFirstResult((page - 1) * size)      // 分页：跳过
  .setMaxResults(size)                    // 分页：取几条
  .getResultList();

// 聚合
em.createQuery("select count(p) from Post p", Long.class).getSingleResult();

// 批量取「每篇文章几条评论」—— 返回 Object[]
em.createQuery("""
        select c.post.id, count(c) from Comment c
         where c.post.id in :ids group by c.post.id
        """, Object[].class)
  .setParameter("ids", ids)
  .getResultStream()
  .collect(Collectors.toMap(r -> (Long) r[0], r -> (Long) r[1]));
☀ JPQL 查的是实体，不是表

select u from User u 里的 User 是类名， u.email 是字段名 —— 不是 users 和 email 列。 大小写敏感，跟着 Java 走。想写真 SQL 用 em.createNativeQuery(...)。

常用注解：

注解管什么注意
@NotNull不能是 null空字符串能过
@NotBlank不能是 null / 空 / 全空白表单字段基本都该用这个
@NotEmpty不能是 null / 空全是空格能过
@Size(min=, max=)字符串长度、集合大小null 直接算通过
@Email邮箱格式规则很宽松，别指望它挡住假邮箱
@Pattern(regexp=)正则记得 ^ 和 $
@Min / @Max数值范围—
@Positive / @PositiveOrZero正数比 @Min(1) 意图清楚
