第 1 章

安装

Flask 自称“微框架”：核心很小，其他功能靠扩展。Hono 也是这个思路，而且更小。 这一章我们把工具装好：Node.js、包管理器、TypeScript，最后建出一个空的 Hono 项目，为下一章的“Hello World”做准备。

本章目标

  • 知道 Hono 由哪几块组成，和 Flask 的组成方式有什么异同
  • 装好 Node.js，并理解“版本管理器”是干什么的
  • 理解 Node.js 为什么不需要 Python 那样的虚拟环境
  • 会用 npm 安装依赖、查看已装的包，读懂 package.json 和 package-lock.json
  • 配好 TypeScript，让 JSX 能够编译成 Hono 的 HTML

Hono 是由什么组成的

原书开篇说：Flask 有三个主要依赖 —— 路由、调试和 WSGI 来自 Werkzeug， 模板来自 Jinja2，命令行来自 Click。 数据库、表单校验、用户认证这些“高级功能”Flask 一概不管，交给扩展。

Hono 的哲学一样，但它连依赖都没有 —— 零依赖，核心只有十几 KB。 它把自己需要的东西都建立在 JavaScript 运行时已经提供的 Web 标准 API 之上：

和 Flask 一样，Hono 不管数据库、不管表单校验、不管用户认证。 好处是你能自己挑最合适的工具：本教程会用 Drizzle 管数据库、Zod 管校验、自己写几十行代码管登录。 坏处是你得知道该挑什么 —— 这正是这套教程要帮你做的事。

ⓘ 关于 Windows

原书建议 Windows 用户使用 WSL（Windows Subsystem for Linux）来获得和 Linux/macOS 一致的命令行体验，这条建议今天依然成立。 不过 Node.js 在 Windows 原生环境下也运行得很好，本教程的代码在两种方式下都能跑。 命令有差异的地方（主要是设置环境变量）会单独标出来。

安装 Node.js

Flask 应用运行在 Python 解释器里；Hono 应用运行在 JavaScript 运行时里。 可选的运行时有 Node.js、Bun、Deno 等，本教程选用最普及的 Node.js（需要 20 以上的版本，推荐最新的 LTS 长期支持版）。

方式一：官方安装包

去 nodejs.org 下载 LTS 版安装包，一路下一步即可。最省事，适合只想先跑起来的人。

方式二：版本管理器（推荐）

做久了你会遇到“这个老项目要 Node 18，那个新项目要 Node 24”的情况。 版本管理器能在一台电脑上装多个 Node 版本并随时切换，相当于 Python 世界的 pyenv。 常用的有 nvm（macOS/Linux）和 fnm（跨平台，更快）： 

# 以 fnm 为例（macOS 可以用 brew install fnm，Windows 可以用 winget install Schniz.fnm）
fnm install --lts
fnm use lts-latest

# 确认装好了
node -v    # v24.x.x
npm -v     # 11.x.x

装 Node.js 时会顺带装上 npm（Node Package Manager），它相当于 Python 的 pip。 社区里还有 pnpm、yarn、bun 等替代品，命令大同小异；本教程统一用 npm。

为什么 Node.js 不需要“虚拟环境”

原书花了不少篇幅讲 Python 虚拟环境：python3 -m venv venv、source venv/bin/activate…… 它要解决的问题是：Python 默认把包装到全局，两个项目需要同一个包的不同版本时就会打架。 虚拟环境给每个项目复制一份“私有的”Python 解释器和包目录。

Node.js 从设计之初就换了一种做法：包默认装在当前项目的 node_modules 文件夹里。 每个项目天然有自己的一份依赖，互不干扰，所以不需要“激活”任何东西。

用 npm 初始化项目

npm init -y

这会生成一个 package.json，它是项目的“身份证”：名字、版本、依赖、以及常用命令。先改一处：

npm pkg set type=module
ⓘ "type": "module" 是什么

JavaScript 历史上有两套模块语法：老的 CommonJS（require()）和新的 ES Module（import / export）。 加上 "type": "module" 表示“这个项目用 ES Module”，这是现在的标准写法，Hono 的所有文档也是这么写的。

安装 Hono

# 运行时依赖：上线时也需要
npm install hono @hono/node-server

# 开发依赖：只在写代码、编译、测试时需要

这几个包各自负责什么：

包作用大致对应原书的

配置 TypeScript

本教程全程使用 TypeScript —— 就是加了类型的 JavaScript。 你可以把类型理解成“写给编辑器看的注释”：写错字段名、传错参数，还没运行编辑器就会标红。 在项目根目录创建 tsconfig.json： 

{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "skipLibCheck": true,
    "jsx": "react-jsx",
    "jsxImportSource": "hono/jsx",
    "outDir": "dist",
    "types": ["node"]
  },
  "include": ["src", "scripts", "tests"]
}

几个值得解释的选项：

  • strict: true：开启严格检查。比如一个值可能是 null，你不先判断就用，编译器会提醒你。刚开始会觉得烦，但它能挡掉大量线上 bug。
  • jsx + jsxImportSource：第 3 章会用 JSX 写页面。这两行告诉 TypeScript：“遇到 <div> 这样的语法，交给 hono/jsx 处理”，而不是交给 React。
  • module: "NodeNext"：按 Node.js 的规则解析模块。它的一个副作用是：导入自己写的文件时要写 .js 后缀（第 7 章会解释为什么）。
  • outDir：上线前用 tsc 编译出的 JavaScript 放到 dist/（第 17 章）。开发时我们用 tsx 直接运行 .ts，不需要先编译。

Hono 官方提供了脚手架：npm create hono@latest flasky，选择 nodejs 模板， 它会把上面这些步骤一次做完。本教程手动一步步来，是为了让你知道每个文件是干什么的。 以后开新项目，直接用脚手架就好。

强烈推荐 VS Code：它对 TypeScript 的支持是内置的， 打开项目文件夹就能看到类型提示、自动补全和错误标红，不用装任何插件。第 18 章会介绍更多工具。

小结

  • Hono 和 Flask 一样是“小核心 + 按需组合”，但核心零依赖，且建立在 Web 标准 API 上。
  • Node.js 用 fnm / nvm 管理版本；npm 负责装包，相当于 pip。
  • Node 的依赖默认装在项目的 node_modules 里，天然隔离，不需要虚拟环境。
  • package.json 记录“想要什么”，package-lock.json 记录“精确装了什么”，两者都提交到 Git；node_modules 不提交。
  • tsconfig.json 里的 jsxImportSource: "hono/jsx" 为第 3 章的 JSX 模板做好了准备。

动手练习

  1. 用 fnm 或 nvm 同时装上两个不同的 Node 版本，练习来回切换，并用 node -v 确认。
  2. 删掉 node_modules 文件夹，然后运行 npm ci，观察它是怎样按 lock 文件完整还原的。
  3. 打开 node_modules/hono/package.json，找到 "dependencies" 字段 —— 验证一下 Hono 是不是真的零依赖。
  4. 试试 npm create hono@latest，对比它生成的文件和我们手动建的有什么不同。
