第 3 章

模板

上一章把 HTML 直接写在处理函数的字符串里，既难维护又不安全。 这一章把“页面长什么样”搬到单独的 JSX 组件里：变量自动转义、布局可以复用、错误页面统一风格， 再加上静态文件和“按用户本地时区显示时间”。

本章目标

  • 理解为什么要把业务逻辑和表现逻辑分开
  • 用 Hono JSX 写页面组件：变量、条件、循环、组件复用
  • 知道 JSX 如何防止 XSS，以及什么时候（极少）需要 raw()
  • 用 jsxRenderer 做一个所有页面共用的布局（相当于 Jinja2 的模板继承）
  • 接入 Bootstrap，做出自定义的 404 / 500 错误页
  • 提供静态文件，并在浏览器里把 UTC 时间换算成本地时间

为什么需要模板

原书这样开篇：处理函数其实身兼两职。以用户注册为例，它既要把新用户写进数据库， 又要生成一个告诉用户“注册成功”的页面。前者叫业务逻辑，后者叫表现逻辑。 把两者混在一起，想象一下用字符串拼接出一个几百行的表格 —— 那会是维护的噩梦。

Flask 用的模板引擎是 Jinja2：一种带 {{ 变量 }} 和 {% 语句 %} 的 HTML 文件。 Hono 提供了两种选择：

📄

hono/html

带自动转义的模板字符串 html`…`。轻量，适合很小的片段。上一章已经见过。

⚛

hono/jsx（本教程采用）

用 JSX 写组件。有类型检查、编辑器补全，组件可以像函数一样组合。它只在服务器上运行，输出纯 HTML 字符串，不是 React。

第一个 JSX 模板

因为文件里要写 JSX，先把入口文件改名为 src/index.tsx（后缀 .tsx 表示“包含 JSX 的 TypeScript”）， 并把 package.json 里 dev 脚本的路径也改一下。然后建一个 src/views 目录放组件：

Jinja2：templates/user.html
<h1>Hello, {{ name }}!</h1>
Hono JSX：src/views/user.tsx
export function UserPage({ name }: { name: string }) {
  return <h1>Hello, {name}!</h1>
}

JSX 组件就是一个函数：参数（叫 props）是要填进页面的数据，返回值是一段标记。 {name} 就相当于 Jinja2 的 {{ name }}。 { name }: { name: string } 这段是 TypeScript：从参数对象里取出 name，并声明它是字符串。

在处理函数里渲染它：

Flask
from flask import render_template

@app.route('/user/<name>')
def user(name):
    return render_template('user.html', name=name)
Hono
import { UserPage } from './views/user.js'

app.get('/user/:name', (c) => {
  return c.html(<UserPage name={c.req.param('name')} />)
})

Flask 的 render_template('user.html', name=name) 用文件名找模板、用关键字参数传数据； JSX 里组件是被 import 进来的函数，name={…} 就是传参。 文件名写错了？TypeScript 在编译期就会告诉你，而不是等到运行时抛 TemplateNotFound。

变量与“过滤器”

JSX 的花括号里可以放任何 JavaScript 表达式，所以 Jinja2 能写的变量形式在这里都有对应：

Jinja2
<p>{{ mydict['key'] }}</p>
<p>{{ mylist[3] }}</p>
<p>{{ mylist[myintvar] }}</p>
<p>{{ myobj.somemethod() }}</p>
JSX
<p>{mydict['key']}</p>
<p>{mylist[3]}</p>
<p>{mylist[myintvar]}</p>
<p>{myobj.somemethod()}</p>

Jinja2 有一套过滤器，用竖线调用：{{ name|capitalize }}。 JSX 不需要专门的过滤器语法 —— 直接调用 JavaScript 的字符串方法或你自己写的函数就行：

Jinja2 过滤器JSX 里的写法
{{ name|upper }} / lower{name.toUpperCase()} / toLowerCase()
{{ name|trim }}{name.trim()}
{{ name|capitalize }}{capitalize(name)}（自己写个两行的函数）
{{ html|striptags }}{html.replace(/<[^>]*>/g, '')}
{{ html|safe }}{raw(html)}（来自 hono/html，见下文）

自动转义：模板最重要的安全功能

原书特别强调了 safe 过滤器：Jinja2 默认会转义所有变量， 把 < 变成 &lt;，这样用户输入的 HTML 会被原样显示成文字，而不会被浏览器执行。 Hono JSX 也一样：{变量} 里的内容永远会被转义。

有时候你确实需要输出一段 HTML（比如第 11 章里 Markdown 转换出的文章正文），这时用 raw()：

import { raw } from 'hono/html'

<div class="post-body">{raw(post.bodyHtml)}</div>
⚠ 只对你确认安全的内容用 raw()

原书原话：“永远不要对不可信的值使用 safe 过滤器，比如用户在表单里输入的文字。” raw() 同理。第 11 章会看到正确的做法：用户写的 Markdown 先在服务器上转成 HTML， 再用白名单清洗一遍，清洗后的结果才能交给 raw()。

控制结构

Jinja2 有自己的 {% if %}、{% for %} 语法。JSX 没有发明新语法，用的全是普通 JavaScript：

条件

Jinja2
{% if user %}
    Hello, {{ user }}!
{% else %}
    Hello, Stranger!
{% endif %}
JSX
{user ? <>Hello, {user}!</> : <>Hello, Stranger!</>}

{/* 只有“如果”没有“否则”时，用 && 更简洁 */}
{isAdmin && <a href="/admin">管理后台</a>}

<>…</> 叫 Fragment（片段），用来把几段内容包成一个整体，本身不会输出任何标签。

循环

Jinja2
<ul>
  {% for comment in comments %}
    <li>{{ comment }}</li>
  {% endfor %}
</ul>
JSX
<ul>
  {comments.map((comment) => (
    <li>{comment}</li>
  ))}
</ul>

宏、导入、包含 → 组件

Jinja2 用宏（macro）定义可复用的模板片段，用 import 从别的文件引入宏，用 include 插入另一个文件。 在 JSX 里，这三件事都是同一个东西 —— 组件：

Jinja2：macros.html + 使用
{% macro render_comment(comment) %}
  <li>{{ comment }}</li>
{% endmacro %}

{% import 'macros.html' as macros %}
<ul>
  {% for comment in comments %}
    {{ macros.render_comment(comment) }}
  {% endfor %}
</ul>
JSX：一个组件 + import
// src/views/components.tsx
export function Comment({ text }: { text: string }) {
  return <li>{text}</li>
}

// 使用的地方
import { Comment } from './components.js'
<ul>
  {comments.map((c) => <Comment text={c} />)}
</ul>

模板继承 → 布局组件

Jinja2 最强大的复用方式是模板继承：基础模板 base.html 定义若干个 {% block %}，子模板用 {% extends %} 继承它，再填充这些块。 JSX 没有继承，但用组合能做到同样的事：布局组件接收 children（子内容）和其他 props：

Jinja2：继承
{# base.html #}
<html>
<head>
  <title>{% block title %}{% endblock %} - My App</title>
</head>
<body>
  {% block body %}{% endblock %}
</body>
</html>

{# index.html #}
{% extends "base.html" %}
{% block title %}Index{% endblock %}
{% block body %}
  <h1>Hello, World!</h1>
{% endblock %}
JSX：组合
import type { PropsWithChildren } from 'hono/jsx'

function Base({ title, children }:
  PropsWithChildren<{ title: string }>) {
  return (
    <html>
      <head><title>{title} - My App</title></head>
      <body>{children}</body>
    </html>
  )
}

function Index() {
  return (
    <Base title="Index">
      <h1>Hello, World!</h1>
    </Base>
  )
}

{% block title %} 变成了 title 属性，{% block body %} 变成了 children。 一个布局需要几个“可填充的位置”，就定义几个 props。Jinja2 的 {{ super() }}（保留父模板的内容再追加）在这里也很自然： 布局里先写固定内容，再输出 props 传进来的额外内容就行。

用 jsxRenderer 让每个页面自动套上布局

每个处理函数都写 <Base title="…">…</Base> 很啰嗦。 Hono 提供了 jsxRenderer 中间件：注册一次布局，之后所有处理函数用 c.render() 只渲染“页面内容”部分，布局会自动包在外面。 

import { jsxRenderer } from 'hono/jsx-renderer'

// 告诉 TypeScript：c.render() 的第二个参数可以带一个 title
declare module 'hono' {
  interface ContextRenderer {
    (content: string | Promise<string>, props?: { title?: string }): Response | Promise<Response>
  }
}

export const renderer = jsxRenderer(({ children, title }) => {
  return (
    <html lang="zh-CN">
      <head>
        <meta charset="utf-8" />
        <meta name="viewport" content="width=device-width, initial-scale=1" />
        <title>{title ? `Flasky - ${title}` : 'Flasky'}</title>
      </head>
      <body>
        <main class="container">{children}</main>
      </body>
    </html>
  )
}, { docType: true })   // 自动在最前面加上 <!DOCTYPE html>

import { renderer } from './views/layout.js'

app.use(renderer)   // 注册成中间件

app.get('/user/:name', (c) => {
  const name = c.req.param('name')
  return c.render(<h1>你好，{name}！</h1>, { title: name })
})
ⓘ 那段 declare module 是什么

c.render() 是 Hono 定义的方法，它默认不知道你的布局要接收 title。 declare module 'hono' 这几行是在“扩充”Hono 的类型声明，告诉编译器：c.render 的第二个参数可以带 title。 这只影响类型检查，不产生任何运行时代码。以后布局要加新参数（比如第 11 章要额外插入脚本），就在这里加一个字段。

接入 Bootstrap

Bootstrap 是一个 CSS 框架，提供现成的按钮、导航栏、表单、提示框样式。 原书用 Flask-Bootstrap 扩展来接入它。其实 Bootstrap 纯粹是浏览器端的东西，服务器只需要在 HTML 里引用它的 CSS 和 JS 文件 —— 在布局组件里加两行就够了，不需要任何扩展： 

<head>
  …
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" />
</head>
<body>
  <nav class="navbar navbar-expand-md navbar-dark bg-dark mb-4">
    <div class="container">
      <a class="navbar-brand" href="/">Flasky</a>
      <button class="navbar-toggler" type="button" data-bs-toggle="collapse" data-bs-target="#nav">
        <span class="navbar-toggler-icon"></span>
      </button>
      <div class="collapse navbar-collapse" id="nav">
        <ul class="navbar-nav me-auto">
          <li class="nav-item"><a class="nav-link" href="/">首页</a></li>
        </ul>
      </div>
    </div>
  </nav>

  <main class="container">{children}</main>

  <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"></script>
</body>
ⓘ JSX 里写 class 还是 className？

React 要求写 className，Hono JSX 两种都支持。因为最终输出的是 HTML，本教程直接写 class， 这样从 Bootstrap 文档里复制过来的代码几乎不用改。另一个区别：JSX 里标签必须闭合，<meta>、<img> 要写成 <meta />、<img />。

自定义错误页面

访问一个不存在的地址时，默认的 404 页面只有一行字，和网站其他页面风格完全不搭。 原书用 @app.errorhandler(404) 和 @app.errorhandler(500) 注册自定义错误页。Hono 里对应的是 app.notFound() 和 app.onError()：

Flask
@app.errorhandler(404)
def page_not_found(e):
    return render_template('404.html'), 404

@app.errorhandler(500)
def internal_server_error(e):
    return render_template('500.html'), 500
Hono
app.notFound((c) => {
  c.status(404)
  return c.render(<ErrorPage status={404} />)
})

app.onError((err, c) => {
  console.error(err)          // 调用栈只写进日志
  c.status(500)
  return c.render(<ErrorPage status={500} />)
})

错误页本身就是个普通组件，因为用了 c.render()，它自动套上了布局，风格和其他页面一致：

const ERROR_TITLES: Record<number, string> = { 403: '禁止访问', 404: '页面不存在', 500: '服务器内部错误' }

export function ErrorPage({ status }: { status: number }) {
  return (
    <div class="page-header">
      <h1>{ERROR_TITLES[status] ?? '出错了'}</h1>
      <p class="text-muted">HTTP {status}</p>
    </div>
  )
}

链接

原书介绍了 url_for()：根据视图函数名生成 URL，而不是在模板里写死路径。 这样以后调整路由，模板里的链接会自动跟着变。例如 url_for('user', name='john', page=2) 返回 /user/john?page=2。

Hono 没有“给路由起名字”的机制，所以也没有 url_for()。日常开发中直接写路径就好， 多个地方用到同一个带参数的地址时，写个小函数集中管理： 

// 需要拼接查询字符串时，用标准的 URLSearchParams，它会正确转义特殊字符
const userUrl = (name: string, page?: number) =>
  `/user/${encodeURIComponent(name)}` + (page ? `?${new URLSearchParams({ page: String(page) })}` : '')

<a href={userUrl('john', 2)}>john 的第 2 页</a>   // → /user/john?page=2

原书还提到 _external=True：生成带协议和域名的完整网址（http://localhost:5000/user/john）。 页面内的链接用相对路径就够了，但发邮件时必须用完整网址（第 8 章）。标准的 URL 类可以做到： 

new URL('/user/john', c.req.url).href   // → 'http://localhost:3000/user/john'

静态文件

除了动态生成的 HTML，网站还有图片、CSS、JavaScript 这类原样发给浏览器的静态文件。 Flask 自动提供一个 /static/<filename> 路由；Hono 需要显式注册 serveStatic 中间件： 

import { serveStatic } from '@hono/node-server/serve-static'

// 请求 /static/styles.css → 读取 ./static/styles.css
app.use('/static/*', serveStatic({ root: './' }))

在项目根目录建一个 static/ 文件夹，放进 favicon.ico 和 styles.css，然后在布局里引用它们：

<link rel="icon" href="/static/favicon.ico" />
<link rel="stylesheet" href="/static/styles.css" />

把时间换算成用户的本地时间

用户分布在世界各地。服务器需要一个统一的时间标准，所以通常存储和处理的都是 UTC（协调世界时）。 但用户希望看到的是自己所在时区、自己习惯格式的时间。

原书的办法很聪明：服务器只输出 UTC 时间，由浏览器用 JavaScript 换算成本地时间 —— 因为只有浏览器知道用户电脑的时区和语言设置。原书用的是 Flask-Moment 扩展（封装了 Moment.js 库）。 如今浏览器内置的 Intl API 已经能完成全部工作，一个库都不用装。

第一步，服务器端组件只负责把时间以标准格式输出，并标记要用哪种显示方式：

export function Moment({ ts, format = 'fromNow' }: { ts: Date; format?: 'fromNow' | 'L' | 'LLL' }) {
  const iso = ts.toISOString()   // '2025-03-06T02:27:46.000Z'，末尾的 Z 表示 UTC
  // 先输出 UTC 时间作为兜底（浏览器禁用 JS 时也能看到），再由脚本替换成本地时间
  return <time datetime={iso} data-format={format}>{iso}</time>
}

第二步，一小段浏览器脚本找到所有 <time data-format>，把内容换成本地时间：

(function () {
  var rtf = new Intl.RelativeTimeFormat(navigator.language, { numeric: 'auto' });
  var units = [['year', 31536000], ['month', 2592000], ['week', 604800],
               ['day', 86400], ['hour', 3600], ['minute', 60], ['second', 1]];

  function fromNow(date) {                    // 相当于 moment(t).fromNow()
    var diff = (date.getTime() - Date.now()) / 1000;
    for (var i = 0; i < units.length; i++) {
      var sec = units[i][1];
      if (Math.abs(diff) >= sec || units[i][0] === 'second')
        return rtf.format(Math.round(diff / sec), units[i][0]);
    }
  }

  var styles = { L: { dateStyle: 'short' }, LLL: { dateStyle: 'long', timeStyle: 'short' } };

  function render() {
    document.querySelectorAll('time[data-format]').forEach(function (el) {
      var date = new Date(el.getAttribute('datetime'));
      var f = el.getAttribute('data-format');
      el.textContent = f === 'fromNow' ? fromNow(date) : date.toLocaleString(undefined, styles[f]);
    });
  }

  render();
  setInterval(render, 60 * 1000);   // 相当于 fromNow(refresh=True)：“3 分钟前”会自己变成“4 分钟前”
})();

把这段脚本作为字符串导出，在布局底部输出。注意要用 raw()，否则 JSX 会把脚本里的 <、& 转义掉：

import { raw } from 'hono/html'
import { momentScript } from './moment.js'

// …布局的 <body> 末尾：
<script>{raw(momentScript)}</script>

最后在首页上试试，对应原书的例 3-13 和 3-14：

app.get('/', (c) => {
  const now = new Date()     // JavaScript 的 Date 内部就是 UTC 时间戳
  return c.render(
    <>
      <h1>Hello World!</h1>
      <p>本地日期和时间是 <Moment ts={now} format="LLL" />。</p>
      <p>那是 <Moment ts={now} />。</p>
    </>,
  )
})
💡 这里用 raw() 是安全的

momentScript 是我们自己写死在代码里的字符串，不包含任何用户输入，所以可以原样输出。 判断能否使用 raw() 的标准永远是：这段内容里，有没有可能混进别人控制的文字？

小结

  • 处理函数负责业务逻辑、准备数据；JSX 组件负责表现逻辑。组件就是返回标记的函数，props 是它的参数。
  • {变量} 自动转义，能挡住 XSS；raw() 相当于 Jinja2 的 |safe，只能用于可信内容。
  • Jinja2 的 if/for 在 JSX 里是 ? :、&& 和 .map()；宏、导入、包含统一成组件。
  • 模板继承在 JSX 里变成组合：布局组件接收 children；jsxRenderer + c.render() 让所有页面自动套上布局。
  • app.notFound() 和 app.onError() 定义自定义错误页；调用栈只写日志，不回给浏览器。
  • 静态文件用 serveStatic；时间在服务器上统一用 UTC，由浏览器的 Intl API 换算成本地时间。

动手练习

  1. 写一个 Base 布局，让它除了 title 之外再接收一个可选的 head prop（用于某些页面追加额外的 <style>），体会“用 props 代替 block”的做法。
  2. 给 403 错误也做一个页面：新增路由 /secret，里面 throw new HTTPException(403)，并在 onError 里根据 err.status 渲染不同的标题。
  3. 在首页显示一个 3 天前的时间（new Date(Date.now() - 3 * 86400_000)），分别用 fromNow 和 L 格式。然后把电脑的系统语言或时区改一下，刷新页面观察变化。
  4. 故意在一个组件里不用 raw() 输出 '<b>粗体</b>'，再用 raw() 输出一次，查看网页源代码里两者的区别。
