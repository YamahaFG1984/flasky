第 2 章

应用的基本结构

这一章写出第一个 Hono 应用，并借它把 Web 应用最核心的机制讲清楚： 请求是怎么找到处理函数的（路由）、处理函数怎么拿到请求信息（Context）、 怎么在每个请求前后插入公共逻辑（中间件）、以及怎么构造各种响应。

本章目标

  • 创建应用实例、定义路由和处理函数，写出完整的 Hello World
  • 用动态路由从 URL 里取参数，并知道为什么要限制参数格式
  • 用 tsx watch 获得“改代码自动重启”的开发体验
  • 理解 Flask 的“上下文全局变量”和 Hono 的 c 参数，各自解决什么问题
  • 用中间件实现 Flask 的请求钩子（before_request / after_request）
  • 构造状态码、响应头、Cookie、重定向和错误响应

初始化：创建应用实例

每个 Flask 应用都要先创建一个应用实例：app = Flask(__name__)。 Web 服务器把收到的所有请求交给这个对象处理。Hono 也一样：

Flask
from flask import Flask
app = Flask(__name__)
Hono
import { Hono } from 'hono'
const app = new Hono()

Flask 需要 __name__ 参数来定位模板和静态文件目录；Hono 不需要任何参数， 因为它不假设你的文件放在哪里 —— 模板是普通的 TypeScript 模块（第 3 章），静态文件目录由你显式指定。

路由和处理函数

浏览器向服务器发请求，服务器交给应用。应用需要知道“这个 URL 该运行哪段代码”， 所以它维护着一张 URL 到函数的映射表。一条映射就叫一个路由（route）。

Flask：装饰器
@app.route('/')
def index():
    return '<h1>Hello World!</h1>'
Hono：方法调用
app.get('/', (c) => {
  return c.html('<h1>Hello World!</h1>')
})

对比一下两边：

  • Flask 用装饰器 @app.route 把函数“登记”成路由；Hono 直接调用 app.get(路径, 处理函数)。 方法名就是 HTTP 方法：app.get、app.post、app.put、app.delete……
  • Flask 把这种函数叫视图函数（view function），Hono 叫处理函数（handler）。
  • Flask 视图返回字符串，框架帮你包成响应；Hono 处理函数必须返回一个 Response， c.html() 就是生成 HTML 响应的快捷方法。
  • 那个 c 是 Context（上下文），本章后半部分会重点讲。

原书还提到一种不用装饰器的注册方式 app.add_url_rule('/', 'index', index)。 Hono 里对应的是 app.on('GET', '/', handler)，适合方法名需要动态决定的场合，平时用得不多。

动态路由

很多网址里带着变量，比如 https://github.com/你的用户名。 Flask 用尖括号 <name> 表示路由的动态部分，Hono 用冒号 :name：

Flask
@app.route('/user/<name>')
def user(name):
    return '<h1>Hello, {}!</h1>'.format(name)
Hono
app.get('/user/:name', (c) => {
  const name = c.req.param('name')
  return c.html(`<h1>Hello, ${name}!</h1>`)
})

Flask 会把动态部分作为参数传给视图函数；Hono 则是在处理函数里用 c.req.param('name') 主动去取。 而且 TypeScript 能从路径字符串 '/user/:name' 里推断出参数名 —— 你写成 c.req.param('nmae') 编辑器就会报错。

Flask 支持 <int:id> 这样的类型转换器，Hono 用正则表达式限制参数格式：

FlaskHono匹配
/user/<name>/user/:name任意不含 / 的一段
/post/<int:id>/post/:id{[0-9]+}只匹配数字，/post/abc 直接 404
/files/<path:p>/files/* 或 /files/:p{.+}可以包含 / 的剩余部分
（需要写两条路由）/api/animal/:type?参数可选
⚠ 参数永远是字符串

:id{[0-9]+} 只是保证“看起来像数字”，c.req.param('id') 拿到的仍然是字符串 '42'。 要当数字用得自己转：Number(c.req.param('id'))。Flask 的 int: 会帮你转，这是两者的一个小差别。

一个完整的应用

把上面的片段组装起来，再加上启动服务器的代码，就是一个完整可运行的应用：

import { serve } from '@hono/node-server'
import { Hono } from 'hono'

const app = new Hono()

app.get('/', (c) => {
  return c.html('<h1>Hello World!</h1>')
})

app.get('/user/:name', (c) => {
  const name = c.req.param('name')
  return c.html(`<h1>Hello, ${name}!</h1>`)
})

// 把 Hono 应用接到 Node.js 的 HTTP 服务器上，监听 3000 端口
serve({ fetch: app.fetch, port: 3000 }, (info) => {
  console.log(`Listening on http://localhost:${info.port}`)
})
📌 原书检查点 2a / 2b：一个路由的 hello.py，以及加上动态路由之后的版本

注意最后几行：app.fetch 就是“传入 Request、返回 Response”的那个函数。

开发服务器

Flask 用 flask run 启动开发服务器。我们在 package.json 里定义一个 dev 脚本： 

npm pkg set scripts.dev="tsx watch src/index.ts"
npm run dev
# Listening on http://localhost:3000

打开浏览器访问 http://localhost:3000/ 就能看到 “Hello World!”； 访问 http://localhost:3000/user/Dave 看到 “Hello, Dave!”； 访问任何没定义的地址，得到 Hono 默认的 404 Not Found。按 Ctrl+C 停止服务器。

调试模式：重载器和调试器

原书的调试模式（FLASK_DEBUG=1）提供两样东西，我们逐一对应：

Flask 调试模式Hono 开发环境
重载器：源文件一改，服务器自动重启 tsx watch 已经做到了：保存文件，服务器在一瞬间重启
调试器：出错时浏览器里显示可交互的调用栈 Hono 没有网页调试器。错误信息打印在终端里；需要断点时用 VS Code 的 JavaScript Debug Terminal 运行 npm run dev，就能在编辑器里打断点、看变量
⚠ 不在网页上暴露调试器，反而是好事

原书特别警告：绝不要在生产服务器上开启 Flask 调试模式，因为网页调试器允许访问者在服务器上执行任意代码。 Hono 根本没有这个东西，默认的错误响应只是一句 Internal Server Error，详细信息只出现在服务器终端。 你以后自己写错误处理（第 3 章）时也要保持这个原则：调用栈只写日志，不回给浏览器。

命令行选项：主机和端口

Flask 的开发服务器默认只接受本机连接，要让局域网里其他电脑访问，需要 flask run --host 0.0.0.0。 Node 服务器默认监听所有网卡，端口则通常从环境变量读取： 

const port = Number(process.env.PORT ?? 3000)
serve({ fetch: app.fetch, port, hostname: '0.0.0.0' })

PORT=8000 npm run dev            # macOS / Linux
$env:PORT=8000; npm run dev      # Windows PowerShell

第 17 章部署时你会发现，几乎所有云平台都通过 PORT 环境变量告诉应用该监听哪个端口，所以从现在起就养成这个习惯。

请求-响应循环

玩过了第一个应用，我们来看看它背后是怎么运转的。

Flask 的上下文 vs Hono 的 c

处理函数需要访问请求信息（URL、请求头、表单……）。最直接的办法是把请求作为参数传进去。 但 Flask 选择了另一条路：它让 request 看起来像一个全局变量，任何地方 from flask import request 就能用。

可是多个请求同时进来时，全局变量怎么可能同时装着不同的请求？ Flask 的答案是上下文（context）：每个线程看到的 request 是不同的对象。 原书列出了四个上下文变量：

Flask 上下文变量含义Hono 里对应的写法
current_app当前应用实例闭包里的 app，或中间件放进 c.var 的配置（第 7 章）
g单个请求内的临时存储c.set('key', v) / c.get('key') / c.var.key
request当前请求c.req
session用户会话第 4 章自己写的会话中间件，放在 c.var.session

Hono 选择了最朴素的办法：把一切都装在参数 c 里传给你。 这不是风格偏好，而是 JavaScript 的运行方式决定的。

🔎 深入：真想要“全局的 c”怎么办

Node.js 有个叫 AsyncLocalStorage 的机制，能做到“在同一条异步调用链里共享一个值” —— 效果和 Flask 的上下文一样。 Hono 把它包装成了 hono/context-storage 中间件，用 getContext() 就能在任意深的函数里拿到当前请求的 c。 但大多数时候显式传参更清晰：看函数签名就知道它依赖请求，测试时也好伪造。本教程只在必要时才这么做。

请求分派：查看路由表

原书在 Python shell 里打印 app.url_map 来查看路由表。Hono 提供了 showRoutes：

import { showRoutes } from 'hono/dev'

showRoutes(app)
// GET  /
// GET  /user/:name

原书的路由表里还有 HEAD 和 OPTIONS。HEAD 请求的意思是“只要响应头，不要正文”。 Hono 同样会自动处理：对 GET 路由发 HEAD 请求，它会运行 GET 处理函数，然后丢掉正文。 OPTIONS 主要用于跨域（CORS）预检，Hono 不会自动响应，需要时加上 hono/cors 中间件。

比如原书用来演示上下文的例子：

app.get('/browser', (c) => {
  const userAgent = c.req.header('User-Agent')
  return c.html(`<p>Your browser is ${userAgent}</p>`)
})
⚠ 把用户输入直接拼进 HTML 是危险的

上面几个例子都把外部传来的字符串（URL 参数、请求头）直接拼进了 HTML。试试访问 /user/%3Cb%3EDave%3C%2Fb%3E —— Hono 会把参数解码成 <b>Dave</b>， 页面上的名字就变成了粗体。换成 <script> 就是一次 XSS 攻击。 （原书的 Flask 例子也有同样的问题。）临时的修复是用 hono/html 的 html 标签函数，它会自动转义： 

import { html } from 'hono/html'
return c.html(html`<h1>Hello, ${name}!</h1>`)   // → &lt;b&gt;Dave&lt;/b&gt;

下一章改用 JSX 模板后，所有变量都会被自动转义，这个问题就从根本上解决了。

请求钩子 → 中间件

有些代码需要在每个请求前后运行：记录日志、连接数据库、识别当前登录的用户…… Flask 提供了四个钩子：before_request、before_first_request、after_request、teardown_request。

Hono 只有一个更通用的概念：中间件（middleware）。 中间件是一个接收 (c, next) 的函数：调用 await next() 之前的代码在处理函数之前运行，之后的代码在处理函数之后运行。 

app.use(async (c, next) => {
  const start = Date.now()          // ← 相当于 before_request
  await next()                      // ← 交给下一层，最终执行到处理函数
  const ms = Date.now() - start     // ← 相当于 after_request
  c.header('X-Response-Time', `${ms}ms`)
})

四个 Flask 钩子在 Hono 里分别这样写：

Flask 钩子Hono 写法
before_request中间件里 await next() 之前的代码。如果直接 return 一个响应（比如重定向），请求就不会到达处理函数
after_request中间件里 await next() 之后的代码，可以通过 c.res 或 c.header() 修改响应
teardown_request用 try { await next() } finally { … }，即使出错也会执行
before_first_request不需要钩子：直接写在模块顶层，服务器启动时就执行一次

原书提到钩子和视图之间常用 g 来传数据，比如 before_request 查出当前用户放进 g.user。 Hono 里用 c.set() 放、c.var 取，而且可以给它声明类型： 

type Env = { Variables: { requestId: string } }
const app = new Hono<Env>()

app.use(async (c, next) => {
  c.set('requestId', crypto.randomUUID())
  await next()
})

app.get('/', (c) => {
  return c.text(`你的请求编号是 ${c.var.requestId}`)  // 类型是 string，拼错名字会报错
})

Hono 还自带了很多现成的中间件，用 app.use() 挂上就行。比如开发时很有用的访问日志： 

import { logger } from 'hono/logger'
app.use(logger())
// <-- GET /user/dave
// --> GET /user/dave 200 2ms

响应

原书说：HTTP 响应不只是一段字符串，它还有状态码和响应头。 Flask 视图可以返回 (正文, 状态码, 响应头) 三元组；Hono 的响应方法都接受同样的三个参数：

Flask
@app.route('/')
def index():
    return '<h1>Bad Request</h1>', 400
Hono
app.get('/', (c) => {
  return c.html('<h1>Bad Request</h1>', 400)
})

常用的响应方法：

c.text('纯文本')                         // Content-Type: text/plain
c.html('<p>HTML</p>')                     // Content-Type: text/html
c.json({ ok: true })                     // Content-Type: application/json
c.body(buffer, 200, { 'Content-Type': 'image/png' })  // 任意内容
c.redirect('/login')                     // 302 重定向
c.notFound()                             // 404

// 也可以直接返回标准的 Response 对象，Hono 完全不拦着
return new Response('hi', { status: 201, headers: { 'X-Custom': 'yes' } })

设置 Cookie 与响应头

原书用 make_response() 先造出响应对象，再调用 set_cookie()。Hono 里 Cookie 和响应头可以在返回之前随时设置：

Flask
from flask import make_response

@app.route('/')
def index():
    response = make_response(
        '<h1>This document carries a cookie!</h1>')
    response.set_cookie('answer', '42')
    return response
Hono
import { setCookie } from 'hono/cookie'

app.get('/', (c) => {
  setCookie(c, 'answer', '42')
  c.header('X-Powered-By', 'Hono')
  return c.html(
    '<h1>This document carries a cookie!</h1>')
})

原书表 2-3 列出的 Flask 响应对象属性，在 Web 标准的 Response 里是这样的：

Flask 响应对象Hono / Web 标准
status_coderes.status；构造时用 c.status(404) 或方法的第二个参数
headersres.headers（一个 Headers 对象）；构造时用 c.header()
set_cookie() / delete_cookie()setCookie(c, …) / deleteCookie(c, …)
content_length / content_typeres.headers.get('Content-Length') / get('Content-Type')
set_data() / get_data()正文在构造时给定；读取用 await res.text()

重定向

重定向是一种特殊的响应：没有页面内容，只有一个状态码 302 和一个 Location 响应头，告诉浏览器“去这个地址”。 它在处理表单时极其常用（第 4 章）。 

app.get('/old-page', (c) => c.redirect('/new-page'))          // 默认 302
app.get('/moved', (c) => c.redirect('https://example.com', 301)) // 永久搬家用 301

中止请求：404 和其他错误

原书用 abort(404) 立即结束请求。abort() 的原理是抛出一个异常。 Hono 里对应的是抛出 HTTPException，或者直接返回 c.notFound()：

Flask
from flask import abort

@app.route('/user/<id>')
def get_user(id):
    user = load_user(id)
    if not user:
        abort(404)
    return '<h1>Hello, {}</h1>'.format(user.name)
Hono
import { HTTPException } from 'hono/http-exception'

app.get('/user/:id', async (c) => {
  const user = await loadUser(c.req.param('id'))
  if (!user) throw new HTTPException(404)
  return c.html(html`<h1>Hello, ${user.name}</h1>`)
})

抛异常的好处和 Flask 一样：它能从任意深的函数调用里“跳出来”，不用一层层 return。 抛出的异常最终由 app.onError() 统一处理 —— 下一章我们会用它做好看的错误页面。

扩展 → 中间件与生态包

原书这一章最后说：Flask 被设计成可扩展的，数据库、认证这些重要功能都交给扩展。 Hono 也一样，只是“扩展”分成了三类：

🧱

内置中间件

hono/logger、hono/cors、hono/csrf、hono/jwt、hono/basic-auth、hono/secure-headers……随 hono 一起安装。

🔧

内置助手

hono/cookie、hono/html、hono/jsx、hono/streaming……不是中间件，是在处理函数里调用的工具函数。

📦

第三方包

@hono/zod-validator 这样的官方周边，以及 Drizzle、Nodemailer 等与框架无关的通用库。

下一章开始，我们用第一个“扩展”—— JSX 模板 —— 把 HTML 从处理函数里搬出去。

小结

  • new Hono() 创建应用；app.get/post(路径, 处理函数) 注册路由；处理函数必须返回 Response。
  • 动态路由用 :name，用 {正则} 限制格式；参数总是字符串。
  • serve({ fetch: app.fetch }) 把应用接到 Node.js；tsx watch 提供自动重载。
  • Flask 的 request、g 等上下文变量，在 Hono 里都在参数 c 上，因为 Node.js 单线程交错执行多个请求。
  • 四种请求钩子统一成中间件：await next() 之前 = before，之后 = after，finally = teardown。
  • 响应 = 状态码 + 响应头 + 正文；c.redirect() 重定向，throw new HTTPException(404) 中止请求。
  • 永远不要把用户输入直接拼进 HTML。

动手练习

  1. 加一个路由 /post/:id{[0-9]+}，返回“第 N 篇文章”。分别访问 /post/42 和 /post/abc，观察区别。
  2. 写一个中间件，给每个响应加上 X-Request-Id 响应头（值用 crypto.randomUUID()），并在处理函数里通过 c.var 读到同一个值。
  3. 用 curl -I http://localhost:3000/ 发一个 HEAD 请求，确认 Hono 返回了响应头但没有正文。
  4. 在 /user/:name 里分别用普通模板字符串和 html`` 输出名字，访问 /user/%3Ci%3Ehi%3C%2Fi%3E 比较两者的页面源代码。
  5. 试着在处理函数里故意写个错误（比如调用一个不存在的函数），看看浏览器和终端各显示了什么。
