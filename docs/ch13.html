第 13 章

用户评论

让用户互动，是社交博客成功的关键。这一章实现评论：存储、提交、分页显示，以及让协管员屏蔽不当评论。 这里用到的技术几乎都是前几章的组合，所以这一章也是一次很好的复习。

本章目标

  • 设计 comments 表，它同时属于一篇文章和一个用户
  • 在文章详情页显示评论、提交评论，并且提交后跳到最后一页
  • 理解 URL 片段（#comments）的作用
  • 用一个组件同时服务“普通显示”和“管理模式”两种场景
  • 实现评论管理页，让协管员屏蔽或恢复评论

评论的数据库表示

评论和文章很像：都有正文、作者和时间，而且都用 Markdown 写。不同的是，评论属于某一篇文章，所以它有两个外键：

  • disabled 是新东西：协管员用它屏蔽不当的评论。原书的列可以为空（None），我们直接给它 notNull().default(false)，省去“空值到底算不算屏蔽”的困惑。
  • 两个外键都级联删除：删文章时它的评论一起删，删用户时他的评论一起删。

评论通常很短，所以原书给评论用了一份更严格的 HTML 白名单：去掉了段落、标题、列表这些块级标签，只留下文字格式。 复用第 11 章的 renderMarkdown()，换一份白名单就行： 

const COMMENT_TAGS = ['a', 'abbr', 'acronym', 'b', 'code', 'em', 'i', 'strong']

export const commentBodyHtml = (body: string) => renderMarkdown(body, COMMENT_TAGS)

export async function createComment(db: Db, postId: number, authorId: number, body: string) {
  const [comment] = await db.insert(comments)
    .values({ body, bodyHtml: commentBodyHtml(body), postId, authorId })
    .returning()
  return comment
}

<p> 不在白名单里会怎样？sanitize-html 默认会去掉标签、保留里面的文字（相当于 Bleach 的 strip=True）， 所以 Good [post](http://example.com)! 会变成 Good <a href="http://example.com">post</a>!，外面的 <p> 被剥掉了。

评论的分页查询。和文章列表一样，一次 JOIN 带出作者信息：

function selectComments(db: Db) {
  return db.select({
    id: comments.id,
    body: comments.body,
    bodyHtml: comments.bodyHtml,
    timestamp: comments.timestamp,
    disabled: comments.disabled,
    postId: comments.postId,
    authorId: comments.authorId,
    author: authorColumns,
  })
    .from(comments)
    .innerJoin(users, eq(comments.authorId, users.id))
}

export async function getPostComments(db: Db, postId: number, page: number, perPage: number) {
  const where = eq(comments.postId, postId)
  if (page === -1) {
    // -1 表示“最后一页”：刚发表的评论在那里
    const total = await db.$count(comments, where)
    page = Math.floor((total - 1) / perPage) + 1
  }
  return paginate(
    page,
    perPage,
    () => db.$count(comments, where),
    (limit, offset) => selectComments(db).where(where)
      .orderBy(asc(comments.timestamp), asc(comments.id)).limit(limit).offset(offset),
  )
}

那个 page === -1 是原书的一个巧妙设计。评论按时间正序排列，新评论总在最后一页。 用户提交评论后，处理函数重定向到 ?page=-1，查询时再把 -1 换算成真正的最后一页，这样用户马上就能看到自己刚写的评论：

const commentSchema = z.object({ body: z.string().trim().min(1, '评论不能为空') })

async function renderPost(c: Context<AppEnv>, extra = {}) {
  const id = Number(c.req.param('id'))
  const post = await getPost(c.var.db, id)
  if (!post) throw new HTTPException(404)

  return c.render(<PostPage post={post} user={c.var.user} comments={comments} {...extra} />, { title: '文章' })
}

URL 片段：#comments

注意重定向地址末尾的 #comments。原书解释：这叫 URL 片段（fragment），用来指定页面加载后的初始滚动位置。 浏览器会找到 id 等于这个值的元素，把它滚动到窗口顶部。评论区的标题就是 <h4 id="comments">评论</h4>。

ⓘ 片段不会发给服务器

# 后面的部分只在浏览器里使用，请求里根本不包含它。所以服务器不需要处理它，也读不到它。 这也意味着：分页导航里的每个页码链接都要自己带上 #comments，否则翻页后又会从页面顶部开始。 第 11 章的 PaginationWidget 预留了 fragment 参数，就是为这里准备的（原书也给分页宏加了同名参数）。 

export function PostPage({ post, user, comments, values, errors }: FormState & {
  post: PostWithAuthor
  user: CurrentUser | null
  comments: Pagination<CommentWithAuthor>
}) {
  return (
    <>
      <PostList posts={[post]} user={user} />
      <h4 id="comments">评论</h4>
      {can(user, Permission.COMMENT) && (
        <form method="post" class="comment-form">
          <Field name="body" label="写下你的评论" values={values} errors={errors} />
          <Submit />
        </form>
      )}
      <CommentList comments={comments.items} />
      <PaginationWidget pagination={comments} href={(p) => `/post/${post.id}?page=${p}`} fragment="#comments" />
    </>
  )
}

文章列表里的评论数

首页和资料页上的每篇文章，都要显示“N 条评论”并链接到评论区。原书在模板里直接写 {{ post.comments.count() }} —— 这意味着每篇文章都要发一次 COUNT 查询，一页 20 篇就是 20 次，又是 N+1。 还记得第 11 章 selectPosts() 里那个评论数子查询吗？它就是为这里准备的，一页文章的评论数在同一条查询里就算好了： 

<a href={`/post/${post.id}#comments`}>
  <span class="badge text-bg-primary">{post.commentCount} 条评论</span>
</a>

管理页把所有文章的评论放在一个列表里，最新的在前面：

main.get('/moderate', loginRequired, permissionRequired(Permission.MODERATE), async (c) => {
  const comments = await getAllComments(c.var.db, pageParam(c), c.var.config.commentsPerPage)
  return c.render(<ModeratePage comments={comments} />, { title: '评论管理' })
})

export async function getAllComments(db: Db, page: number, perPage: number) {
  return paginate(
    page,
    perPage,
    () => db.$count(comments),
    (limit, offset) => selectComments(db)
      .orderBy(desc(comments.timestamp), desc(comments.id)).limit(limit).offset(offset),
  )
}

一个组件，两种模式

原书的管理页复用了 _comments.html，但它需要在管理模式下多显示一些东西。为此原书用了 Jinja2 的一个技巧： 在 include 之前用 {% set moderate = True %} 定义一个变量，被包含的模板能看到它。 组件不需要这种隐式的变量传递 —— 直接加一个 moderate 属性： 

export function CommentList({ comments, moderate = false, page = 1 }: {
  comments: CommentWithAuthor[]
  moderate?: boolean
  page?: number
}) {
  return (
    <ul class="comments">
      {comments.map((comment) => (
        <li class="comment">
          <div class="comment-thumbnail">
            <a href={`/user/${comment.author.username}`}>
              <img class="rounded profile-thumbnail" src={gravatar(comment.author, 40)} alt="" />
            </a>
          </div>
          <div class="comment-content">
            <div class="comment-date"><Moment ts={comment.timestamp} /></div>
            <div class="comment-author"><a href={`/user/${comment.author.username}`}>{comment.author.username}</a></div>
            <div class="comment-body">
              {comment.disabled && <p><i>这条评论已被管理员屏蔽。</i></p>}
              {(moderate || !comment.disabled) && (comment.bodyHtml ? raw(comment.bodyHtml) : comment.body)}
            </div>
            {moderate && (
              <form method="post" action={`/moderate/${comment.disabled ? 'enable' : 'disable'}/${comment.id}?page=${page}`}>
                {comment.disabled
                  ? <button class="btn btn-outline-secondary btn-sm">恢复</button>
                  : <button class="btn btn-danger btn-sm">屏蔽</button>}
              </form>
            )}
          </div>
        </li>
      ))}
    </ul>
  )
}

export function ModeratePage({ comments }: { comments: Pagination<CommentWithAuthor> }) {
  return (
    <>
      <div class="page-header"><h1>评论管理</h1></div>
      <CommentList comments={comments.items} moderate page={comments.page} />
      <PaginationWidget pagination={comments} href={(p) => `/moderate?page=${p}`} />
    </>
  )
}

屏蔽和恢复

两个按钮分别提交到“屏蔽”和“恢复”两个路由。原书用的是 GET 链接，我们用 POST 小表单（修改数据的操作都用 POST，理由见第 8 章）。 两个路由几乎一样，用一个循环注册： 

for (const action of ['enable', 'disable'] as const) {
  main.post(`/moderate/${action}/:id{[0-9]+}`, loginRequired, permissionRequired(Permission.MODERATE), async (c) => {
    const ok = await setCommentDisabled(c.var.db, Number(c.req.param('id')), action === 'disable')
    if (!ok) throw new HTTPException(404)
    return c.redirect(`/moderate?page=${pageParam(c)}`)     // 回到刚才那一页
  })
}

export async function setCommentDisabled(db: Db, id: number, disabled: boolean) {
  const rows = await db.update(comments).set({ disabled }).where(eq(comments.id, id)).returning({ id: comments.id })
  return rows.length > 0          // 0 行被更新 = 评论不存在
}

注意按钮表单的 action 里带着 ?page=当前页，处理函数重定向时把它原样带回去。 原书特别提到这一点：协管员翻到第 5 页屏蔽了一条评论，处理完应该还停在第 5 页，而不是被送回第 1 页。

小结

  • comments 表有两个外键（作者、文章），各自构成一对多；disabled 用 notNull().default(false) 避免三态。
  • 评论的 Markdown 用更严格的白名单，块级标签被剥掉但保留文字。
  • 提交评论后重定向到 ?page=-1#comments：-1 换算成最后一页，片段让浏览器滚动到评论区；分页链接也要带上片段。
  • 文章列表的评论数来自第 11 章的子查询，而不是每篇文章单独 COUNT。
  • CommentList 组件用 moderate 属性切换两种显示，代替 Jinja2 的 {% set %} + include。
  • 屏蔽 / 恢复用 POST，带着页码往返，保持协管员的位置。
